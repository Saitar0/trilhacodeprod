# 4.2 — HTML semântico

## Objetivo
Organizar uma página usando elementos semânticos do HTML e justificar a escolha de cada um conforme o significado e a função do conteúdo.

## Teoria

### Significado além da aparência
HTML semântico usa elementos que comunicam a função do conteúdo a navegadores, tecnologias assistivas, mecanismos de busca e outras ferramentas. Uma `<div>` é um contêiner genérico; ela pode agrupar conteúdo quando não há um elemento mais específico apropriado. Não escolha elementos apenas pelo estilo visual que o navegador aplica por padrão — CSS controla apresentação, HTML expressa estrutura e significado.

### Elementos estruturais comuns
- `<header>` reúne conteúdo introdutório de uma página ou seção, como título e elementos de apoio.
- `<nav>` agrupa navegação principal ou relevante.
- `<main>` identifica o conteúdo principal da página; normalmente há um `main` principal visível.
- `<section>` agrupa conteúdo temático, geralmente identificado por um título.
- `<article>` representa conteúdo independente ou que pode fazer sentido por si, como uma publicação.
- `<aside>` contém informação complementar relacionada ao conteúdo ao redor.
- `<footer>` reúne informações de encerramento da página ou seção, como autoria ou links auxiliares.

Esses elementos podem ser aninhados conforme a estrutura real. O nome do elemento não substitui uma hierarquia de títulos clara. Uma seção não é automaticamente necessária para todo grupo visual e um `article` não é apenas um cartão com borda.

### Exemplo de estrutura

```html
<header><h1>Diário de viagens</h1></header>
<nav aria-label="Navegação principal">
  <a href="/">Início</a>
  <a href="/destinos">Destinos</a>
</nav>
<main>
  <article>
    <header><h2>Uma semana em Recife</h2></header>
    <p>Relato da viagem...</p>
    <aside><p>Melhor época: consulte a previsão local.</p></aside>
  </article>
</main>
<footer><p>© Diário de viagens</p></footer>
```

O exemplo é uma possibilidade, não um molde universal. Escolha a estrutura que descreve o conteúdo que existe.

### Títulos e regiões de navegação
Elementos de seção e títulos trabalham juntos para tornar a estrutura compreensível. Em geral, use um `<h1>` para o assunto principal da página e organize os subtítulos sem pular níveis sem motivo; escolha o nível pelo relacionamento hierárquico do conteúdo, não pelo tamanho visual desejado. O estilo é responsabilidade do CSS.

Use `<nav>` para um conjunto significativo de links de navegação, como o menu do site ou um índice. Um grupo pequeno de links relacionados não precisa ser `nav` se não tiver essa função. Uma página pode ter navegação principal e navegação auxiliar; dê a cada região um nome que ajude a distingui-las quando isso for necessário. `<header>` e `<footer>` também podem pertencer a uma página ou a um conteúdo como `article`, conforme a posição e o contexto.

## Resumo
- Semântica comunica o papel do conteúdo, independentemente de sua aparência.
- Use elemento específico quando ele corresponde ao significado; `div` é contêiner genérico.
- `header`, `nav`, `main`, `section`, `article`, `aside` e `footer` têm usos distintos.
- `section` agrupa tema; `article` representa conteúdo independente; `aside` é complementar.
- Títulos expressam hierarquia; `nav` identifica navegação significativa, não qualquer conjunto de links.
- A aparência vem de CSS; títulos e elementos semânticos não devem ser escolhidos só pelo estilo padrão.

## Verificação — quiz
1. Qual elemento identifica o conteúdo principal da página? **A)** `main`. **B)** `aside`. **C)** `footer`. **D)** `span`. **Resposta: A.**
2. Quando `article` é uma escolha plausível? **A)** Para qualquer caixa visual. **B)** Para conteúdo independente que pode fazer sentido fora do contexto imediato, como uma publicação. **C)** Para estilizar texto em negrito. **D)** Para substituir CSS. **Resposta: B.**
3. Qual diferença melhor descreve `section` e `div`? **A)** `section` agrupa tema semanticamente; `div` é contêiner genérico. **B)** São idênticos em semântica. **C)** `div` sempre cria navegação. **D)** `section` é apenas para imagens. **Resposta: A.**
4. O elemento `<nav>` deve conter: **A)** qualquer grupo de links, sem contexto. **B)** uma seção de navegação significativa. **C)** todo o conteúdo da página. **D)** o rodapé. **Resposta: B.**
5. Avalie as afirmações: **I.** Um grupo deve virar `<section>` sempre que precisar de uma borda visual. **II.** Um `<header>` ou `<footer>` pode introduzir ou encerrar a página inteira ou um conteúdo como um `<article>`. **A)** Apenas I. **B)** Apenas II. **C)** I e II. **D)** Nenhuma. **Resposta: B.** A aparência não determina semântica; CSS pode estilizar um contêiner genérico, e `header`/`footer` dependem do contexto em que aparecem.

## Prática — três níveis

Faça as atividades em ordem. Em cada uma, explique o significado de suas escolhas; não use um elemento só para obter uma aparência padrão.

### 1. Guiada — mapeie o conteúdo para regiões

Um portal de viagens contém: nome do site; links principais para “Destinos” e “Guias”; um relato de viagem que pode ser lido independentemente; uma caixa com informação complementar sobre o clima; e dados de autoria e licença no encerramento do relato e da página.

**Tarefa:** associe cada conteúdo ao elemento ou região mais adequado e explique em uma frase por que `article`, `aside`, `nav` e `footer` não são intercambiáveis.

| Conteúdo | Elemento/região escolhida | Motivo |
|---|---|---|
| Nome do site e introdução |  |  |
| Links principais |  |  |
| Relato independente |  |  |
| Informação complementar sobre clima |  |  |
| Autoria do relato |  |  |
| Licença e links gerais do site |  |  |

**Gabarito comentado:** nome e introdução cabem no `header` da página; links principais no `nav`; o relato no `main` e em um `article`; o clima em um `aside` se for complementar ao relato; autoria no `footer` do `article`; licença e links gerais no `footer` da página. Um `footer` dentro do artigo encerra aquele conteúdo; o `footer` da página encerra a página. O `aside` acrescenta informação relacionada, e o `nav` é reservado a navegação significativa.

### 2. Independente — desenhe a estrutura de um portal de cursos

Escreva o esqueleto HTML de uma página para um portal fictício. O conteúdo deve ter: cabeçalho do site; navegação principal; uma área principal; uma seção intitulada “Trilhas disponíveis” com dois links para trilhas; uma publicação independente de aviso; uma área complementar com datas; e rodapé do site. Inclua títulos em níveis coerentes e use `div` somente se houver um motivo genérico de agrupamento ou apresentação.

**Entregue:** o HTML e uma tabela curta com pelo menos cinco decisões semânticas, incluindo por que os links das trilhas não tornam automaticamente cada cartão um `article`, e por que o aviso independente pode ser um `article`.

**Dicas progressivas**

- Comece pelo único conteúdo principal da página. Depois, identifique tema, publicação independente e informação complementar.
- As duas trilhas são destinos de navegação apresentados dentro de uma seção temática; o cartão visual não define sozinho o elemento. O aviso tem autoria/data e pode fazer sentido fora do portal.

**Critérios de autocorreção (0–2 pontos cada; total 10)**

- Usa `header`, `nav`, `main` e `footer` conforme o papel de cada região.
- A seção de trilhas tem título e agrupa conteúdo temático.
- O aviso é modelado como `article` quando se sustenta sozinho, com título próprio.
- As datas aparecem como complemento, sem substituir o conteúdo principal.
- Os níveis de títulos acompanham a hierarquia e as escolhas são justificadas pelo significado, não pela aparência.

Considere a atividade concluída com pelo menos 8 pontos. Se houver divergência, justifique a estrutura pelo conteúdo apresentado e revise se `section` tem um tema identificável.

### 3. Transferência — reestruture uma página existente

Receba ou crie uma página composta quase só por `div`. Identifique cabeçalho, navegação, conteúdo principal, grupos temáticos, conteúdo independente, informação complementar e encerramento. Substitua contêineres apenas quando houver correspondência semântica e escreva uma justificativa curta para cada mudança. Revise os títulos e confirme que a hierarquia continua compreensível sem depender da aparência visual.

**Aceite:** elementos escolhidos correspondem ao conteúdo; há somente um `main` principal visível; navegação está identificada; seções têm tema e título claro; `div` permanece onde um contêiner genérico é adequado; a hierarquia de títulos não foi escolhida pelo tamanho visual.

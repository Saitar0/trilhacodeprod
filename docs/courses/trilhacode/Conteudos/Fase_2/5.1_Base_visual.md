# 5.1 — Base visual

## Objetivo
Estilizar uma página com seletores, cascata, especificidade, box model, display, position, cores, tipografia e espaçamento, prevendo o efeito das regras aplicadas.

## Teoria

### Regras e seletores
CSS (Cascading Style Sheets) descreve a apresentação dos elementos. Uma regra contém um seletor e declarações. Seletores podem apontar para elementos (`p`), classes (`.aviso`), IDs (`#topo`), estados (`:hover`) e relações entre elementos. Prefira classes com nomes relacionados à função do componente; IDs devem ser únicos e seletores excessivamente específicos dificultam manutenção.

```css
.card {
  color: #263238;
  padding: 1rem;
  border: 1px solid #cfd8dc;
}
```

### Cascata e especificidade
Quando várias declarações podem definir a mesma propriedade, o navegador resolve conflitos considerando relevância, origem/importância, camadas, especificidade, escopo e ordem de aparição. Para o nível inicial, compare regras da mesma origem e camada: uma regra mais específica tende a vencer; quando especificidade empata, a última declaração aplicável vence. `!important` altera a prioridade e deve ser evitado como correção padrão.

### Box model
Um elemento em caixa tem conteúdo, padding, borda e margem. `width` e `height` controlam a caixa de conteúdo no modelo padrão; padding e borda são acrescentados. `box-sizing: border-box` faz largura/altura incluírem padding e borda, o que frequentemente torna o dimensionamento mais previsível.

### Display e position
`display` determina como a caixa participa do layout: `block` ocupa uma linha no fluxo normal, `inline` participa do fluxo de texto, `inline-block` combina comportamentos, e `flex`/`grid` criam contextos de layout. `position: relative` mantém o elemento no fluxo e cria referência para descendentes posicionados; `absolute` remove a caixa do fluxo normal e posiciona em relação ao bloco de referência; `fixed` acompanha a viewport; `sticky` alterna conforme a rolagem e limites do contêiner. Use posicionamento para relações específicas, não como substituto geral de Flexbox/Grid.

### Cor, tipografia e espaçamento
Cores devem manter contraste suficiente. Escolha fontes legíveis e uma escala tipográfica consistente; fontes do sistema reduzem dependências. Use espaçamento para mostrar agrupamentos, preferindo uma escala pequena e consistente. Unidades relativas como `rem` facilitam acompanhar preferências de tamanho de texto; medidas fixas podem ser adequadas para bordas ou detalhes.

## Resumo
- CSS separa apresentação da estrutura HTML.
- Seletor escolhe elementos; declarações definem propriedades e valores.
- Cascata resolve conflitos; especificidade e ordem importam, mas não explicam sozinhas todas as prioridades.
- Box model: conteúdo, padding, borda e margem; `border-box` inclui padding e borda na largura definida.
- `display` define participação no layout; `position` altera posicionamento e relação com o fluxo.
- Contraste, tipografia e espaçamento afetam legibilidade.

## Verificação — quiz
1. Considere as regras, ambas aplicáveis ao mesmo parágrafo e sem `!important`:

```css
 p { color: #333; }
 .aviso { color: #a00; }
```

O elemento `<p class="aviso">Falha</p>` fica de que cor? **A)** `#333`, porque seletor de elemento sempre vence. **B)** `#a00`, porque a classe tem maior especificidade. **C)** Depende de qual regra aparece por último, mesmo com especificidades diferentes. **D)** O navegador ignora as duas. **Resposta: B.** A classe tem maior especificidade que o seletor de elemento. Ordem só desempata declarações com prioridade e especificidade equivalentes; espaços no seletor não determinam a vitória.
2. No box model padrão, o que fica entre conteúdo e borda? **A)** Margin. **B)** Padding. **C)** Position. **D)** Display. **Resposta: B.** A sequência é conteúdo, padding, borda e margin. `display` e `position` não são camadas da caixa.
3. Um elemento usa `width: 300px; padding: 20px; border: 2px solid`. Com `box-sizing: border-box`, qual é a largura externa total? **A)** 300 px. **B)** 340 px. **C)** 344 px. **D)** 260 px. **Resposta: A.** A largura declarada já inclui padding e borda. Sem `border-box`, a soma seria 344 px; 260 px seria a largura de conteúdo calculada nesse exemplo.
4. Qual afirmação sobre `position: absolute` é correta? **A)** Mantém sempre o espaço original no fluxo. **B)** Remove a caixa do fluxo normal e posiciona conforme um bloco de referência. **C)** É obrigatório para grid. **D)** Só funciona em texto. **Resposta: B.** Elementos absolutos não reservam o espaço que ocupariam no fluxo normal. Grid não exige `absolute`, e posicionamento não se limita a texto.
5. Você quer que o conteúdo principal tenha largura legível, mas que se adapte a telas menores. Qual regra é o melhor ponto de partida? **A)** `width: 900px` em qualquer viewport. **B)** `width: 100%; max-width: 70rem; margin-inline: auto;`. **C)** `position: absolute; left: 20rem;`. **D)** `white-space: nowrap;`. **Resposta: B.** A largura fluida respeita telas estreitas, o limite evita linhas excessivamente longas e as margens automáticas centralizam quando há espaço. Largura fixa e posicionamento absoluto podem causar overflow; `nowrap` impede que o texto quebre.

## Práticas

### 1. Guiada — preveja e corrija uma cascata
Sem executar o código primeiro, preveja as cores aplicadas e explique o motivo. Depois confirme no navegador.

```html
<p class="aviso" id="status">Perfil salvo</p>
```

```css
p { color: #333; }
.aviso { color: #a00; }
#status { color: #075; }
.aviso { color: #06c; }
```

**Tarefa:** anote a cor final; indique qual regra perde e por quê; então altere somente uma regra para que o texto fique `#a00` sem usar `!important`.

**Dicas graduais:** (1) marque os seletores que correspondem ao parágrafo; (2) compare elemento, classe e ID; (3) só use a ordem do arquivo para desempatar declarações da mesma especificidade.

**Solução comentada:** a cor final é `#075`, porque `#status` tem maior especificidade que as classes e o seletor de elemento. A última regra `.aviso` não vence o ID. Para obter `#a00` com uma única alteração, mude o valor na regra `#status` para `#a00`. Evite aumentar especificidade sem necessidade. Confirme no painel de estilos qual declaração está ativa e quais foram sobrescritas.

**Erro comum:** dizer que a última regra sempre vence. A ordem é critério de desempate, não substitui a comparação de prioridade e especificidade.

### 2. Independente — diagnóstico de box model e legibilidade
Na página das unidades 4.1/4.2, escolha um cartão, seção ou formulário. Use as ferramentas do navegador para registrar `width`, `padding`, `border` e `margin`, e desenhe ou descreva as quatro camadas do box model. Em seguida, proponha uma pequena escala de espaçamento com três valores e explique onde os aplicaria.

**Entregáveis:** (a) elemento inspecionado e dimensões observadas; (b) cálculo da largura externa com a configuração atual; (c) regra de CSS usando `box-sizing: border-box`; (d) amostra da escala de espaçamento aplicada a dois elementos.

**Dicas graduais:** (1) diferencie a largura do conteúdo da largura total; (2) verifique o `box-sizing` calculado; (3) compare o cálculo com o diagrama do navegador.

**Aceite e resposta esperada:** as camadas aparecem na ordem conteúdo → padding → borda → margin; o cálculo explica se padding e borda somam à largura declarada; os valores da escala são reutilizados e têm função visível. Os números dependem da página escolhida, então registre a evidência do DevTools em vez de usar um gabarito numérico fixo.

### 3. Transferência — estilize e revise uma página
Estilize a página de currículo usando CSS externo. Defina tipografia, paleta com contraste legível, espaçamento consistente, largura de leitura, estados de link e estilo de formulário. Inclua duas regras concorrentes e explique qual declaração prevalece. Use DevTools para inspecionar a caixa de um elemento e registrar dimensões de conteúdo, padding, borda e margem.

**Entregue:** link ou arquivo da página, trecho das regras concorrentes, previsão e resultado observado no navegador, diagrama ou registro do box model e uma nota curta sobre legibilidade em viewport estreita.

**Aceite:** conflito explicado por prioridade/especificidade/ordem aplicáveis; box model descrito com valores; layout não depende de posicionamento absoluto para estrutura geral; texto permanece legível, links distinguíveis e foco de teclado perceptível. Se algum critério falhar, registre a correção e repita a inspeção.

**Rubrica (0–2 por critério):** (1) previsão da cascata justificada; (2) box model calculado e conferido; (3) escolhas visuais consistentes e legíveis; (4) revisão em viewport estreita e com teclado. `0` = ausente/incorreto, `1` = parcial, `2` = claro e demonstrado. Pronto com pelo menos 6/8 pontos e sem falha de legibilidade ou foco identificada sem plano de correção.

## Critério de conclusão
Prever o resultado de conflitos simples de especificidade, explicar a cascata em contexto e descrever o box model de um elemento inspecionado.

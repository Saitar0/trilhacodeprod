# 5.3 — Responsividade

## Objetivo
Adaptar uma interface a diferentes larguras com medidas flexíveis e media queries, usando abordagem mobile first ou desktop first de forma justificada.

## Teoria

### Layout adaptável
Design responsivo é uma abordagem para que o conteúdo funcione em diferentes larguras, orientações, resoluções e formas de interação. Não significa criar uma versão para cada modelo de dispositivo. Estruture conteúdo em fluxo normal, prefira limites flexíveis e deixe os componentes crescerem ou se reorganizarem conforme o espaço.

Medidas como `%`, `rem`, `em`, `vw` e funções `min()`, `max()` e `clamp()` podem expressar dimensões relativas. `max-width` limita a largura de conteúdo; imagens fluidas costumam usar `max-width: 100%` para não ultrapassar o contêiner.

### Viewport e conteúdo fluido
Inclua `<meta name="viewport" content="width=device-width, initial-scale=1">` no documento para que navegadores móveis usem a largura do dispositivo como viewport de layout. Sem essa configuração, o navegador pode apresentar uma viewport virtual mais larga e reduzir a página inteira.

Use limites para evitar extremos. Por exemplo, `width: min(100% - 2rem, 70rem); margin-inline: auto;` deixa uma margem em telas estreitas e limita linhas longas em telas amplas. `clamp(mínimo, valor preferido, máximo)` permite uma variação entre limites, mas não substitui teste de legibilidade; valores tipográficos não devem ficar pequenos demais nem crescer sem controle.

### Media queries e breakpoints
Uma media query aplica CSS quando uma condição sobre o ambiente é atendida. Breakpoint é o ponto em que uma mudança de layout melhora a leitura ou o uso; escolha-o observando o conteúdo, não copiando uma lista de dispositivos.

```css
.layout { display: grid; grid-template-columns: 1fr; }

@media (min-width: 48rem) {
  .layout { grid-template-columns: 2fr 1fr; }
}
```

### Mobile first e desktop first
**Mobile first** começa com um layout simples para espaço estreito e adiciona capacidades em telas maiores com `min-width`. **Desktop first** começa com o layout amplo e adapta/remova elementos para telas menores, com frequência usando `max-width`. Ambos podem funcionar; escolha a abordagem coerente com o conteúdo e mantenha as regras fáceis de entender.

Flexbox e Grid podem responder naturalmente ao espaço disponível, às vezes sem media queries. Use uma media query quando a composição realmente precisar mudar, não para corrigir toda diferença com valores arbitrários.

### Teste orientado pelo conteúdo
Não existe uma largura que represente todos os dispositivos. Redimensione a viewport e observe onde a navegação quebra, as linhas ficam difíceis de ler, os cartões comprimem ou aparece rolagem horizontal. Registre a largura aproximada do problema e crie um breakpoint onde a mudança de composição o resolve. Teste também conteúdo variável (títulos longos, traduções, imagens) e zoom; uma captura em três larguras é evidência útil, mas não garante funcionamento em todo contexto.

## Resumo
- Responsividade atende a espaços e contextos variados, sem depender de modelos específicos de aparelho.
- Prefira fluxo, medidas flexíveis e limites de largura; imagens não devem exceder o contêiner.
- Media queries aplicam regras sob condições; breakpoints vêm de necessidades do conteúdo.
- Mobile first amplia progressivamente; desktop first adapta a partir da tela ampla.
- Flexbox e Grid já permitem layouts flexíveis; media queries são úteis quando a composição precisa mudar.
- A meta viewport permite que a largura de layout em dispositivos móveis corresponda à largura do dispositivo; dimensões fluidas devem ter limites testados.
- Verifique o layout em larguras variadas e mantenha o conteúdo legível e operável.

## Verificação — quiz
1. Como escolher um breakpoint? **A)** Pela marca do celular mais vendido. **B)** No ponto em que o conteúdo ou layout precisa mudar para continuar utilizável. **C)** Sempre em 768px. **D)** Um por componente, sem testar. **Resposta: B.** O breakpoint responde a uma necessidade observada no conteúdo; uma largura fixa universal ou a marca de um aparelho não prova que a composição funciona.
2. O que descreve mobile first? **A)** Começar com layout para espaço estreito e acrescentar ajustes para espaços maiores. **B)** Fazer site apenas para celular. **C)** Usar somente pixels. **D)** Desativar Grid. **Resposta: A.** A abordagem começa pelo espaço limitado e amplia progressivamente; não restringe o público a celular nem proíbe unidades ou ferramentas.
3. Flexbox/Grid podem produzir layout responsivo sem media query? **A)** Nunca. **B)** Sim, em muitos casos; use queries quando a composição precisar mudar. **C)** Só com framework. **D)** Apenas em impressão. **Resposta: B.** Os modelos podem ajustar distribuição e faixas sem um breakpoint; a query continua apropriada quando a estrutura precisa mudar.
4. Qual é o objetivo de `max-width: 100%` em uma imagem? **A)** Evitar que ultrapasse a largura do contêiner. **B)** Fazer a imagem sempre ocupar 100vw. **C)** Cortá-la. **D)** Ocultar a imagem. **Resposta: A.** A imagem pode encolher até caber no espaço disponível, mas não é forçada a preencher toda a viewport e não é cortada por essa regra.
5. A página fica reduzida e com texto minúsculo no celular, embora o CSS tenha uma regra para telas estreitas. Qual é uma primeira verificação importante? **A)** Se o HTML contém a meta viewport. **B)** Se todo elemento está `position: fixed`. **C)** Se o breakpoint usa exatamente 768px. **D)** Se o site usa uma tabela. **Resposta: A.** Sem a meta viewport, o navegador pode usar uma viewport de layout virtual mais larga e reduzir a página. Depois de verificar essa configuração, investigue as regras e teste o conteúdo em diferentes larguras.

## Práticas

### 1. Guiada — investigue overflow e viewport
Considere o documento e as regras abaixo. Em uma tela estreita, a página tem rolagem horizontal e uma faixa de conteúdo muito pequena.

```html
<head>
  <title>Agenda</title>
  <link rel="stylesheet" href="styles.css">
</head>
<main class="conteudo">
  <img src="evento.jpg" alt="Pessoas em uma oficina">
  <h1>Programação completa do encontro de desenvolvimento web</h1>
</main>
```

```css
.conteudo { width: 960px; margin: 0 auto; }
img { width: 800px; }
```

**Tarefa:** identifique as causas prováveis, proponha uma sequência mínima de correções e diga o que observaria após cada mudança.

**Dicas graduais:** (1) verifique as dimensões fixas; (2) confira se há configuração de viewport; (3) defina largura fluida com limite e permita que a imagem caiba no contêiner.

**Solução comentada:** adicione `<meta name="viewport" content="width=device-width, initial-scale=1">`; limite `.conteudo` com largura fluida, por exemplo `width: min(100% - 2rem, 70rem); margin-inline: auto;`; use `img { max-width: 100%; height: auto; }`. Teste uma largura estreita e outra ampla. Se o título ainda causar uma linha desconfortável, decida onde a composição ou tipografia deve mudar, em vez de adicionar um breakpoint sem evidência.

**Erros comuns:** reduzir toda a página com zoom; trocar 960 px por outro valor fixo; definir `width: 100vw` sem considerar margens e barras de rolagem; esconder o overflow sem encontrar o elemento que o causa.

### 2. Independente — encontre o ponto de mudança pelo conteúdo
Na página que você construiu, teste a viewport reduzindo-a gradualmente. Registre ao menos dois pontos em que algo deixa de funcionar (ou explique, com evidência, por que não encontrou problema): por exemplo, navegação quebra, cartões ficam estreitos, título cria linhas ruins, imagem excede o contêiner ou controles ficam difíceis de usar.

Entregue uma tabela `Largura aproximada | Evidência do problema | Mudança proposta | Resultado após corrigir`. Implemente uma estratégia mobile first ou desktop first e uma media query somente onde a composição precisar mudar. Indique também uma situação em que Flexbox/Grid resolvem o ajuste sem query.

**Dicas graduais:** (1) use o conteúdo real, inclusive seu título mais longo; (2) redimensione em intervalos pequenos perto do ponto de falha; (3) compare se uma regra fluida resolve antes de criar breakpoint.

**Critérios de aceite:** observação reproduzível, breakpoint ligado ao problema observado, estratégia identificada e pelo menos um comportamento fluido sem media query. As larguras e soluções variam com o HTML, então justificativa e evidência são o gabarito.

### 3. Transferência — adapte uma referência em três larguras
Adapte a página de referência em três larguras representativas: estreita, intermediária e ampla. Primeiro redimensione a viewport e registre onde texto, navegação, imagens ou cartões deixam de funcionar. Depois ajuste medidas e composição. Inclua pelo menos uma media query e indique se a estratégia é mobile first ou desktop first.

**Entregue:** capturas ou observações nas três larguras, valores aproximados testados, trechos de CSS antes/depois, motivo do breakpoint e um caso de conteúdo variável que você verificou.

**Aceite:** sem rolagem horizontal inesperada; textos e controles continuam legíveis/operáveis; imagens cabem no contêiner; navegação e cartões se reorganizam; breakpoints têm justificativa ligada ao conteúdo. Registre as larguras verificadas, sem tratá-las como garantia para todos os dispositivos.

**Rubrica (0–2 por critério):** (1) identifica problemas com evidência; (2) usa medidas fluidas e limites apropriados; (3) breakpoint/estratégia justificados; (4) verifica três larguras e conteúdo variável. `0` = ausente/incorreto, `1` = parcial, `2` = claro e reproduzível. Pronto com pelo menos 6/8 e sem overflow ou conteúdo ilegível sem plano de correção.

## Critério de conclusão
Layout funciona nas três larguras testadas, sem quebra relevante, e a pessoa explica as medidas relativas, a media query e a abordagem escolhida.

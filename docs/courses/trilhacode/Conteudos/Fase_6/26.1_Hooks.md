## Objetivo
Escolher e usar Hooks segundo a responsabilidade que atendem: manter regras de chamada, sincronizar com sistemas externos usando Effects, guardar valores imperativos em refs e aplicar memoização sem depender dela para a correção.

## Teoria

## Microtópico 1 — Hooks obedecem a regras de chamada

Hooks permitem que componentes funcionais usem estado, contexto, efeitos e outras capacidades do React. Os Hooks fornecidos pelo React começam com use, como useState e useEffect. Custom Hooks também começam com use e podem compor outros Hooks para reaproveitar lógica com estado.

Chame Hooks somente no nível superior do corpo de um componente funcional ou custom Hook. Não os coloque dentro de condições, loops, funções aninhadas, blocos try ou após uma saída antecipada. React associa estado e efeitos à ordem em que os Hooks são chamados; manter essa ordem igual entre renderizações permite associar cada valor ao Hook correto.

```jsx
function Status({ enabled }) {
  const [count, setCount] = useState(0);

  if (!enabled) {
    return <p>Desativado</p>;
  }

  useEffect(() => {
    document.title = "Contagem: " + count;
  }, [count]);

  return <button onClick={() => setCount((value) => value + 1)}>{count}</button>;
}
```

O exemplo viola a regra porque, quando enabled é false, o componente retorna antes de chamar useEffect. Corrija mantendo todos os Hooks no topo e tornando a lógica condicional dentro do Hook, ou extraindo a parte condicional para outro componente. Uma custom Hook compartilha lógica; cada chamada mantém seu próprio estado. Ela não cria estado compartilhado entre componentes automaticamente.

## Microtópico 2 — useEffect sincroniza um sistema externo

UseEffect coordena um componente com algo que o React não controla diretamente: conexão, assinatura de evento, timer, API imperativa do navegador ou integração externa. Seu código define um ciclo de configuração e, quando necessário, uma limpeza que desfaz a configuração.

```jsx
useEffect(() => {
  const connection = createConnection(roomId);
  connection.connect();

  return () => connection.disconnect();
}, [roomId]);
```

A lista de dependências inclui todos os valores reativos lidos pelo efeito — props, estado e variáveis/funções criadas no componente. Quando uma dependência muda, React executa a limpeza com os valores antigos e depois configura com os novos; ao desmontar, executa a limpeza final. Não silencie o linter para esconder dependência ausente; ajuste o código para que o efeito leia apenas os valores realmente necessários.

Se a lógica não sincroniza com sistema externo, provavelmente não precisa de Effect. Calcular dados derivados pertence à renderização; responder a clique pertence ao handler. Copiar filteredItems para outro estado em um Effect adiciona uma renderização e duas fontes de verdade. Em desenvolvimento, Strict Mode pode executar um ciclo extra de configuração e limpeza para encontrar efeitos sem limpeza adequada; uma sequência configurar → limpar → configurar deve ser segura.

## Microtópico 3 — useRef mantém um valor que não desenha a tela

useRef guarda um objeto cuja propriedade current persiste entre renderizações. Alterar current não pede uma renderização. Essa característica serve para referência a elemento DOM ou informação imperativa cuja mudança não precisa aparecer na UI, como o identificador de um timer.

```jsx
const inputRef = useRef(null);

function focusInput() {
  inputRef.current?.focus();
}

return (
  <>
    <input ref={inputRef} aria-label="Buscar" />
    <button onClick={focusInput}>Focar busca</button>
  </>
);
```

Se a mudança deve aparecer na tela, use estado, não ref. Não leia ou altere current durante a renderização para produzir JSX; isso faz a descrição depender de uma mutação que React não acompanha. Para atualizar um objeto/array visível, use o setter de estado com um valor novo.

## Microtópico 4 — useMemo e useCallback otimizam valores diferentes

useMemo guarda o resultado de uma função de cálculo enquanto suas dependências permanecem iguais. Pode evitar repetir um cálculo comprovadamente caro ou manter identidade de um objeto quando isso habilita uma otimização. A função é executada durante renderização quando necessário; por isso o cálculo deve ser puro.

useCallback guarda a própria função para manter sua identidade entre renderizações até uma dependência mudar. Não chama a função armazenada. Pode ajudar quando a função é prop para um componente memoizado ou é dependência de outro Hook; não é necessário para todo handler.

```jsx
const visibleItems = useMemo(
  () => filterItems(items, filter),
  [items, filter]
);

const handleSelect = useCallback((id) => {
  onSelect(id);
}, [onSelect]);
```

Ambos recebem todas as dependências reativas usadas pela função. Omitir uma dependência pode congelar um valor antigo e criar defeitos sutis. Memoização é uma otimização, não uma condição de correção: se retirar useMemo ou useCallback muda o resultado do programa, procure o erro de lógica.

O React Compiler, quando instalado e habilitado no projeto, pode automatizar várias memoizações. Não presuma que existe só porque o código usa React. Verifique configuração e medição antes de escrever otimizações manuais; elas podem reduzir re-renderizações em alguns casos, mas também aumentam a quantidade de conceitos e dependências que a equipe mantém.

## Microtópico 5 — Escolha pelo problema e confira o ciclo

Antes de adicionar um Hook, formule o problema:
- Preciso manter um valor que muda a interface? Estado.
- Preciso sincronizar conexão, assinatura ou outra API externa? Effect, com dependências e limpeza.
- Preciso acessar um nó DOM ou guardar informação imperativa que não desenha a UI? Ref.
- Preciso evitar um cálculo ou identidade referencial comprovadamente custosos? Avalie memoização e meça.
- Preciso compartilhar lógica com estado entre componentes? Custom Hook; lembre que cada chamada possui sua própria instância de estado.

Para um Effect, trace setup, valores reativos, situação que dispara nova configuração e limpeza. Para memoização, observe o perfil antes/depois e confirme que as dependências incluem as entradas. Para ref, confirme que mudar current não deveria ser motivo para atualizar a tela. Essa análise evita usar um Hook conhecido por hábito, em vez de resolver uma necessidade.

## Resumo
- Chame Hooks no topo de componentes ou custom Hooks, na mesma ordem em todas as renderizações.
- useEffect sincroniza com sistema externo; dependências refletem valores reativos e limpeza desfaz a configuração.
- useRef persiste valor imperativo sem renderizar; use state para dados que precisam alterar a UI.
- useMemo conserva resultado de cálculo; useCallback conserva função; ambos são otimizações com dependências completas.
- Custom Hooks reutilizam lógica, não a mesma instância de estado; React Compiler só deve ser considerado quando configurado no projeto.

## Quiz

1. **Diagnóstico:** um componente chama useEffect somente quando isOpen é true. Qual é o problema e como reorganizar?  
   **Resposta esperada:** Hook em condição quebra a ordem de chamadas. Chame o Hook no topo e trate isOpen dentro do efeito, ou mova o conteúdo para um componente separado.

2. **Escolha de ferramenta:** é preciso focar um input após clicar num botão, sem que a própria referência determine conteúdo visível. Qual Hook é apropriado?  
   **Resposta esperada:** useRef para obter o elemento DOM e chamar focus no handler; mudar current não deve ser usado para atualizar a UI.

3. **Limpeza:** um efeito registra um listener de resize e depende de uma configuração atual. O que precisa acontecer quando a configuração muda e quando o componente sai da tela?  
   **Resposta esperada:** remover o listener anterior antes de registrar o novo e removê-lo na desmontagem; declarar a configuração reativa usada como dependência.

4. **Distinção:** qual a diferença entre useMemo e useCallback?  
   **Resposta esperada:** useMemo retorna o resultado calculado e o conserva; useCallback conserva a definição da função e não a executa.

5. **Avaliação:** useMemo é necessário para que o filtro de uma lista seja correto?  
   **Resposta esperada:** não. O filtro deve funcionar sem memoização; useMemo só se justifica por ganho de desempenho medido ou identidade referencial necessária.

## Atividades práticas

### Atividade 1 — Audite e reorganize a chamada de Hooks

**Desafio:** corrija um componente que chama useEffect dentro de uma condição, useRef para armazenar o texto visível e usa useMemo para todo valor calculado.

**Passos:**
1. Identifique quais dados precisam renderizar a interface e quais são apenas imperativos.
2. Mova todos os Hooks ao topo do componente antes de retornos condicionais.
3. Use estado para o texto que aparece na tela e mantenha a ref apenas se houver uma necessidade imperativa, como foco.
4. Remova Effect que só copia um valor derivado e calcule esse valor durante a renderização.
5. Explique por que cada Hook restante é apropriado.

**Dica:** não basta mover o Hook de lugar se o trabalho dentro dele continuar sem necessidade.

**Solução de referência:** todos os Hooks chamados no topo; estado guarda texto visível; ref aponta para nó que recebe foco; valor derivado calculado no render; o efeito condicional pode retornar cedo dentro do setup ou ficar em componente específico, mantendo dependências corretas. Memoização sem necessidade sai.

**Rubrica:** regras de chamada respeitadas; state/ref separados por responsabilidade; Effects só sincronizam exterior; dependências coerentes; decisão sobre cada Hook tem justificativa.

### Atividade 2 — Sincronize uma assinatura com limpeza

**Desafio:** um componente se inscreve em atualizações de uma sala e precisa trocar de assinatura quando roomId muda.

**Passos:**
1. Defina o que o setup cria e qual função libera a inscrição.
2. Escreva um Effect que lê roomId e registra a assinatura correta.
3. Retorne a limpeza que remove a assinatura correspondente ao valor usado no setup.
4. Descreva a sequência ao montar, trocar roomId e desmontar.
5. Simule em desenvolvimento setup → cleanup → setup e verifique que não ficam listeners duplicados.

**Dica:** a limpeza deve fechar sobre a assinatura criada naquele ciclo; não remova um listener diferente por engano.

**Solução de referência:** setup cria handle/subscription para o roomId atual e registra o listener; cleanup remove essa assinatura específica. Dependência [roomId] faz React limpar e configurar novamente ao trocar sala. Na desmontagem remove a última assinatura; repetir o primeiro ciclo em desenvolvimento não deixa duplicatas.

**Rubrica:** setup e limpeza são correspondentes; dependências incluem roomId; troca e desmontagem não deixam listener ativo; repetição em desenvolvimento permanece correta.

### Atividade 3 — Justifique ou retire memoização

**Desafio:** uma lista filtrada fica lenta em um conjunto grande, mas o time também adicionou useCallback em todos os handlers sem medir.

**Passos:**
1. Defina como reproduzir e medir a lentidão com dados representativos.
2. Use o profiler para identificar cálculo ou componente que consome tempo.
3. Aplique useMemo somente ao cálculo caro com dependências completas, se a medição justificar.
4. Para cada useCallback, identifique componente memoizado ou dependência de Hook que precisa de identidade estável.
5. Compare resultado, comportamento e perfil antes/depois; remova otimização que não tenha benefício observável.

**Dica:** primeiro verifique se renderizações repetidas são problema real; criar uma função por render não é, por si só, um defeito.

**Solução de referência:** garantir filtro puro e correto; medir antes; memoizar visibleItems em [items, filter] apenas se houver ganho; manter callback apenas se estabilizar prop de componente memoizado ou dependência necessária. O resultado da interface é o mesmo com e sem memoização; a diferença deve estar em desempenho medido.

**Rubrica:** gargalo reproduzível definido; Hook selecionado para a causa observada; dependências completas; sem alegar correção baseada em memo; comparação informa manter ou remover.

## Critério de conclusão
Para useEffect, useRef, useMemo e useCallback, explique a necessidade que cada um resolve e quando não usar; demonstre dependências e limpeza coerentes e respeite as regras de chamada em um componente funcional.

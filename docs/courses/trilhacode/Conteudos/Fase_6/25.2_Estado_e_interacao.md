## Objetivo
Construir uma lista interativa de tarefas com estado, eventos, condições, atualização imutável de coleções e formulário controlado, explicando como a UI acompanha os dados.

## Teoria

## Microtópico 1 — Estado é a memória que muda a interface

Props descrevem dados recebidos do componente pai; **estado** é memória que pertence à interface e pode mudar com o tempo. Em um componente funcional, o Hook useState fornece o valor desta renderização e uma função para pedir a atualização. O estado não é uma variável comum que o componente altera diretamente.

Quando o componente chama o setter, React registra a atualização e pode renderizar o componente novamente com o novo estado. A variável lida pelo handler atual continua sendo a fotografia da renderização em que esse handler foi criado. Por isso, ler a variável imediatamente depois do setter não mostra o valor atualizado nessa mesma execução.

```jsx
const [count, setCount] = useState(0);

function increment() {
  setCount((current) => current + 1);
}
```

A forma funcional usa o estado anterior no momento em que React processa a atualização. É especialmente apropriada quando o novo valor depende do anterior, como incrementar, alternar um booleano ou adicionar item à coleção. Se o próximo valor é independente do anterior — por exemplo, definir o filtro para “concluídas” — passe o valor diretamente.

## Microtópico 2 — Eventos pedem mudanças; renderização descreve o resultado

Passe uma função ao evento, como onClick={handleClick}; não execute handleClick() durante a renderização. A função do evento representa uma ação que acontecerá quando a pessoa interagir. Dentro dela, faça a alteração de estado apropriada; React calculará a UI de acordo com o novo estado.

React pode agrupar atualizações feitas durante um evento. Se três atualizações dependem de um valor anterior e todas usam o mesmo snapshot, definir repetidamente valor + 1 pode produzir uma única elevação, em vez de somar três. Usar a forma funcional permite que cada atualização receba o resultado da anterior.

```jsx
function addThree() {
  setCount((current) => current + 1);
  setCount((current) => current + 1);
  setCount((current) => current + 1);
}

return <button onClick={addThree}>Somar três</button>;
```

Use uma expressão inline somente quando ela continuar clara, como onClick={() => removeTask(task.id)}. Evite chamar o handler ao montar o JSX, porque isso executaria a lógica durante a renderização e o resultado da chamada poderia ser passado ao evento por engano.

## Microtópico 3 — Atualize arrays e objetos sem mutar o estado

Arrays e objetos guardados em estado devem ser tratados como somente leitura. Não use push, splice ou atribuição a uma propriedade do objeto existente e depois passe a mesma referência ao setter. Crie uma nova coleção e, quando um item mudar, também crie um novo objeto para esse item.

- Adicionar: criar array novo com spread ou concat.
- Remover: criar array novo com filter.
- Atualizar um item: mapear e retornar cópia com os campos alterados.
- Ordenar: copiar a lista primeiro e ordenar a cópia, pois sort altera o array.

A cópia de um array é superficial. Copiar a lista não autoriza alterar um objeto que continua compartilhado dentro dela. Copie o item que muda também.

```jsx
function toggleTask(id) {
  setTasks((current) =>
    current.map((task) =>
      task.id === id
        ? { ...task, completed: !task.completed }
        : task
    )
  );
}
```

Cada elemento diretamente renderizado por map precisa de key única entre irmãos e estável ao longo das renderizações. Use ID associado aos dados. Não gere key aleatória durante renderização; ela muda a cada chamada e impede React de reconhecer a continuidade do item. O índice só é adequado em listas estáticas que nunca reordenam, inserem ou removem itens; prefira identidade do dado para tarefas editáveis. Key é uma pista para React, não uma prop recebida automaticamente pelo componente filho.

## Microtópico 4 — Derive condições e filtros do estado essencial

A interface condicional escolhe o que apresentar a partir dos dados atuais. Uma lista vazia pode exibir orientação; uma lista preenchida pode mostrar resultados. Se o filtro muda, derive a coleção visível de tasks e filter em vez de armazenar também visibleTasks como estado separado.

```jsx
const visibleTasks = tasks.filter((task) => {
  if (filter === "active") return !task.completed;
  if (filter === "completed") return task.completed;
  return true;
});

const completedCount = tasks.filter((task) => task.completed).length;
```

Armazenar tarefas e também uma cópia atualizada de tarefas visíveis ou de contadores cria duas fontes de verdade. Se uma mudança atualiza uma delas e esquece outra, a UI diverge. Guarde a entrada que muda e calcule valores simples derivados durante a renderização. Use estado separado quando representar uma informação realmente independente que muda — por exemplo, qual filtro foi selecionado.

Considere os estados visuais importantes: lista vazia, lista com itens, filtro sem resultados e item concluído. Expressões condicionais no JSX tornam o resultado de cada estado explícito; não esconda nem mostre elementos alterando manualmente o DOM.

## Microtópico 5 — Formulário controlado mantém uma fonte clara

Em um campo controlado, value vem do estado e onChange atualiza esse estado no evento de entrada. Atualize de forma síncrona no handler; se o valor fornecido ao campo não acompanhar a digitação, React volta a mostrar o valor antigo. Associe um label ao input e indique o tipo e as instruções necessários.

```jsx
const [title, setTitle] = useState("");

<form onSubmit={handleSubmit}>
  <label htmlFor="task-title">Nova tarefa</label>
  <input
    id="task-title"
    value={title}
    onChange={(event) => setTitle(event.target.value)}
  />
  <button type="submit">Adicionar</button>
</form>
```

O formulário deve tratar submit no onSubmit para aceitar clique no botão e envio pelo teclado. Use preventDefault quando o navegador não deve navegar/recarregar a página. Valide o conteúdo antes de adicionar, apresente mensagens compreensíveis e limpe o campo depois de uma operação bem-sucedida, se esse for o comportamento desejado. Geração de ID acontece uma vez no handler de criação ou na camada de dados, nunca em cada renderização.

Há casos para campos não controlados, mas nesta unidade o controle por estado deixa explícita a sincronização entre dado e tela. Não guarde como estado uma string que pode ser derivada trivialmente de outras fontes sem necessidade.

## Resumo
- useState dá valor da renderização atual e setter que pede uma atualização; o snapshot do handler não muda no meio da execução.
- Passe funções aos eventos e use atualizador funcional quando o próximo valor depende do anterior.
- Crie novos arrays e objetos em vez de mutar estado; keys devem identificar dados de modo estável.
- Derive listas filtradas e contadores do estado essencial para evitar fontes duplicadas.
- Em input controlado, value e onChange mantêm campo e estado sincronizados; use label e submit sem recarga indesejada.

## Quiz

1. **Snapshot:** depois de chamar setCount(count + 1), o que console.log(count) no mesmo handler deve mostrar?  
   **Resposta esperada:** o valor da renderização que criou o handler; o setter solicita atualização para uma renderização posterior, não reescreve essa variável local.

2. **Escolha de atualização:** três ações no mesmo handler devem acrescentar uma unidade ao valor atual. Qual forma evita que todas usem o mesmo snapshot?  
   **Resposta esperada:** três atualizadores funcionais, como setCount(current => current + 1); cada um recebe o resultado atualizado na fila.

3. **Diagnóstico:** um item foi removido com tasks.splice(index, 1) e setTasks(tasks). Por que isso pode não atualizar a UI de modo correto?  
   **Resposta esperada:** splice muta a coleção existente e o setter recebe a mesma referência. Use filter ou outra operação que produza novo array.

4. **Identidade:** ao reordenar e remover cartões, por que key baseada no índice pode associar estado local ao cartão errado?  
   **Resposta esperada:** a posição muda, mas o índice continua identificando posições; React pode tratar um item diferente como o mesmo. Um ID estável acompanha o dado.

5. **Modelo da tela:** deve-se guardar tasks, visibleTasks e completedCount em três estados independentes?  
   **Resposta esperada:** geralmente não. Guarde tasks e a escolha de filter; derive a lista visível e o total durante a renderização para evitar valores desatualizados.

## Atividades práticas

### Atividade 1 — Construa uma lista interativa

**Desafio:** implemente uma lista de tarefas que permita adicionar, concluir e remover itens sem mutar estado.

**Passos:**
1. Defina tarefa com id, title e completed e inicialize estado com lista vazia.
2. Crie um formulário com label e campo controlado para adicionar título.
3. No submit, impeça recarga, valide título não vazio após trim, crie ID estável uma vez e acrescente por meio de novo array.
4. Alterne conclusão usando map e remova usando filter.
5. Confirme que o estado de um cartão não troca de identidade quando outro item é removido.

**Dica:** gere ID ao tratar submit, não dentro de tasks.map durante a renderização.

**Solução de referência:** o componente guarda tasks e title. O submit normaliza e valida title, pede atualização funcional com array acrescido do objeto novo e limpa o campo se adicionou. Cada botão de concluir chama função com ID e map cria cópia do item; remover filtra pelo ID. Renderização usa task.id como key e mostra texto vazio quando não há itens.

**Rubrica:** todas as ações funcionam; nenhum array/item existente é mutado; formulário acessível e sem recarga acidental; IDs persistem entre renderizações; lista vazia tem estado compreensível.

### Atividade 2 — Adicione filtros e estados de interface

**Desafio:** estenda a lista para mostrar todas, ativas ou concluídas; apresente contagem e mensagens diferentes para lista vazia e filtro sem resultados.

**Passos:**
1. Adicione um estado filter com valor inicial explícito.
2. Crie controles para alterar filtro; os handlers devem passar função ou valor correto.
3. Derive visibleTasks e completedCount de tasks e filter.
4. Diferencie “ainda não há tarefas” de “há tarefas, mas o filtro não encontra resultados”.
5. Verifique que concluir ou remover item atualiza contagem e lista filtrada.

**Dica:** a coleção completa responde se há alguma tarefa; a coleção filtrada responde se há resultado neste filtro.

**Solução de referência:** manter somente tasks e filter como dados necessários; calcular completedCount e visibleTasks em cada renderização. Se tasks estiver vazia, mostrar convite de criação; se tasks tiver itens e visibleTasks estiver vazia, explicar que o filtro não encontrou resultados. Alternar completed atualiza o item por ID e os dados derivados acompanham.

**Rubrica:** não duplica estado derivado; vazios têm mensagens semanticamente diferentes; contagem acompanha estado; filtro funciona com conclusão e remoção.

### Atividade 3 — Corrija uma lista com estado defeituoso

**Desafio:** diagnostique quatro defeitos: atualizar tarefa com mutação direta, key por índice, executar handler no JSX e campo com value sem onChange.

**Passos:**
1. Localize para cada defeito a regra React que está sendo violada.
2. Reescreva atualização de tarefa com map e cópia do item.
3. Substitua key por ID estável da tarefa.
4. Passe a referência do handler ou uma função que o invoque somente no evento.
5. Conecte value a onChange e teste digitação, envio e remoção/reordenação.

**Dica:** diferencie a função handler do resultado de chamá-la; um handler não deve rodar enquanto React calcula a interface.

**Solução de referência:** map retorna um novo array e um objeto novo somente para o item alterado; key usa task.id; onClick recebe handleClick ou uma arrow que passa o ID quando clicada; input atualiza title no onChange. Os testes manuais cobrem digitação, submissão, atualização, reordenação e identidade correta após remoção.

**Rubrica:** cada um dos quatro defeitos é corrigido pela causa; identidade permanece associada ao dado; campo aceita entrada; ações só ocorrem no evento; explica o comportamento observado.

## Critério de conclusão
Implemente adicionar, concluir, remover e filtrar tarefas com estado imutável, formulário controlado e keys estáveis; explique o snapshot do handler e derive ao menos um valor em vez de duplicá-lo em estado.

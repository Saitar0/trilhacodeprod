## Objetivo
Reconhecer o que React Native reutiliza do React e da lógica de uma aplicação web e o que precisa ser adaptado para componentes, APIs e comportamento de plataformas nativas.

## Microtópico 1 — Reutilize o modelo React, não o renderizador HTML
React Native compartilha o modelo declarativo do React: componentes, props, estado, composição e hooks continuam úteis. O que muda é a forma de desenhar a interface. Em vez de elementos HTML do DOM, use componentes fundamentais como `View`, `Text`, `TextInput`, `Pressable`, `Image` e listas nativas como `FlatList`. Texto precisa estar dentro de `Text`; uma `View` não funciona como um `div` que aceita texto solto.

Estilo é escrito em objetos JavaScript, com propriedades como `backgroundColor` em camelCase. Há conceitos familiares do CSS, como Flexbox, mas o conjunto de propriedades e alguns comportamentos diferem. Também mudam teclado, toque, rolagem, áreas seguras da tela e integração com recursos do aparelho. Uma tela pode compartilhar a regra de negócio, mas seu layout precisa ser desenhado e validado para os controles nativos.

## Microtópico 2 — Compartilhe lógica e adapte o que depende da plataforma
Código de domínio, validação e uma camada HTTP podem ser reutilizados quando não dependem de `window`, DOM, CSS ou bibliotecas específicas do navegador. Componentes web não se tornam componentes nativos por serem escritos em React; `div`, estilos CSS e APIs de browser precisam de alternativa ou adaptação.

Quando uma diferença é pequena, `Platform` permite escolher um valor ou implementação para iOS e Android. Quando a interface ou integração é substancialmente diferente, arquivos como `Componente.ios.tsx` e `Componente.android.tsx` podem separar as implementações mantendo uma API comum. Não crie bifurcações sem necessidade: compartilhe a parte que realmente tem comportamento igual e prove a compatibilidade em cada destino.

Acessibilidade, teclado, permissões e recursos nativos precisam ser avaliados no aparelho ou simulador apropriado. VoiceOver e TalkBack têm diferenças de plataforma, e um teste visual em navegador não garante que rótulos, foco ou gestos funcionem como esperado em um app nativo.

## Microtópico 3 — Entenda o papel do framework e da distribuição
Além da tela, um aplicativo móvel precisa de navegação, acesso a APIs nativas, build para iOS/Android e preparação para distribuição. O React Native recomenda começar com um framework como Expo para a maioria dos novos apps; usar React Native sem um framework continua possível quando há uma necessidade ou restrição específica. Expo é uma escolha do ecossistema, não um requisito para compreender o modelo de componentes.

Escolha ferramentas conforme o projeto e verifique quais recursos exigem módulos nativos, configuração de plataforma, permissões ou builds específicos. A lógica compartilhada pode reduzir duplicação, mas não elimina a necessidade de testar interação, aparência e integrações em iOS e Android.

## Resumo
- Componentes, props, estado e hooks vêm do modelo React; a interface é renderizada por componentes nativos, não por HTML do DOM.
- Lógica independente do navegador pode ser compartilhada; DOM, CSS e APIs web exigem adaptação.
- `Platform` e extensões `.ios`/`.android` ajudam a expressar diferenças reais entre plataformas.
- Acessibilidade, teclado, permissões, APIs nativas e distribuição precisam de validação móvel.
- Expo é o framework recomendado pelo projeto React Native para a maioria de novos apps, mas não é a única forma suportada de criar um app.

## Flashcards
- **React Native usa `<div>`?** Não. Usa componentes como `View`, `Text` e `Pressable`, que são mapeados para elementos nativos.
- **Hooks e validação de domínio podem ser reaproveitados?** Sim, se a lógica não depender de DOM ou de APIs exclusivas do navegador.
- **Uma tela React web funciona automaticamente em iOS e Android?** Não. Componentes, estilos, acessibilidade e APIs precisam ser adaptados e verificados nas plataformas alvo.

## Atividades

### Atividade 1 — Traduza um componente web para a linguagem nativa
Escolha um cartão simples de produto feito para web. Esboce a versão React Native usando `View`, `Text`, `Image` e `Pressable`; indique o que pode reutilizar da lógica e o que precisa de layout e interação próprios. **Entrega:** esboço ou componente demonstrável e uma lista breve de decisões de adaptação.

**Critério:** não há elementos HTML/CSS tratados como nativos; conteúdo textual, ação e hierarquia continuam compreensíveis.

### Atividade 2 — Faça um mapa de compartilhamento e diferenças
Para uma tela de login, classifique validação, cliente HTTP, campos, navegação, teclado e permissão como compartilháveis, adaptáveis ou específicos de plataforma. Escolha um caso que varie entre Android e iOS e proponha `Platform` ou arquivos específicos; explique como o verificaria com leitor de tela e teclado. **Entrega:** matriz curta e plano de verificação.

**Critério:** a classificação tem justificativa; a proposta testa ambas as plataformas e não presume equivalência só porque o código usa React.

## Critério de conclusão
Explique pelo menos duas partes reutilizáveis (como lógica de validação e hooks) e duas partes que exigem implementação ou verificação nativa (como componentes de interface, teclado, permissões, acessibilidade ou distribuição).

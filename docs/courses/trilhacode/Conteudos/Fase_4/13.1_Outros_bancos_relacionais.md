## Objetivo
Reconhecer conceitos relacionais compartilhados e diferenças entre PostgreSQL, MySQL/MariaDB, Oracle Database e SQL Server, sem presumir compatibilidade total entre produtos ou versões.

## Teoria

### 1. Separe conceitos relacionais de detalhes do produto
Bancos relacionais organizam dados em relações/tabelas e oferecem conceitos como chaves, joins, constraints e transações. Isso facilita transferir conhecimento, mas não garante que um mesmo script ou comportamento funcione sem ajustes em todos os SGBDs.

MySQL e MariaDB têm histórias e pontos de compatibilidade, mas são produtos distintos, com versões e recursos que evoluem separadamente. Oracle Database e Microsoft SQL Server também possuem dialetos, ferramentas e ecossistemas próprios. Nesta fase, PostgreSQL é o banco usado nas práticas; os demais entram como repertório para leitura e comparação.

**Flashcards**
- **Pergunta:** SQL padrão garante que todas as funções e comportamentos sejam iguais em qualquer SGBD? **Resposta:** não. **Lembrete:** há extensões, diferenças de implementação e recursos que variam por versão.
- **Pergunta:** MySQL e MariaDB são o mesmo produto? **Resposta:** não, são produtos distintos. **Lembrete:** compatibilidade em alguns recursos não garante equivalência completa.

### 2. Compare o dialeto em um caso concreto
Uma diferença pode aparecer em algo simples, como paginação. PostgreSQL e MySQL 8.4 aceitam `LIMIT ... OFFSET`. No SQL Server, paginação usa `ORDER BY ... OFFSET ... ROWS FETCH NEXT ... ROWS ONLY` e exige ordenação. Em todos, a consulta precisa de uma ordem explícita e estável para que páginas sejam previsíveis.

**PostgreSQL ou MySQL 8.4:**
```sql
SELECT id, nome
FROM produto
ORDER BY id
LIMIT 10 OFFSET 20;
```

**SQL Server:**
```sql
SELECT id, nome
FROM produto
ORDER BY id
OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;
```

Não extrapole uma diferença observada para todo o dialeto. Verifique produto, versão e feature específica na documentação oficial. Uma sintaxe que existe em uma versão pode ter limites ou semântica diferente em outra.

**Flashcard**
- **Pergunta:** o que verificar ao portar uma consulta ou schema? **Resposta:** sintaxe, tipos, funções, paginação, identidade/sequences, NULL, upsert, transações, migrations, driver e plano de execução. **Lembrete:** valide cada item na versão e configuração de destino.

### 3. Planeje migração com evidências
Migrar significa validar comportamento e dados, não trocar apenas o nome do driver. Faça um inventário do schema e das consultas importantes; identifique recursos específicos; confirme como os tipos e constraints são representados; confira funções de data, paginação, geração de IDs, upsert, locking e isolamento. Em seguida, execute testes de compatibilidade com dados representativos e compare resultados, não apenas se o script compila.

Considere também operação: backup e restore, permissões, ferramentas de migration, monitoramento, custo de execução e plano para voltar ou corrigir. Uma tabela genérica de “compatibilidade total” tende a esconder diferenças de versão e de configuração. Registre a fonte oficial e a versão que confirmou cada conclusão.

**Erro comum:** concluir que uma migração foi bem-sucedida porque DDL e consultas foram aceitos, sem comparar semântica, dados, transações e comportamento operacional.

## Resumo
- Conceitos relacionais transferem entre produtos; detalhes de sintaxe e comportamento variam.
- MySQL e MariaDB são produtos diferentes, mesmo com áreas de compatibilidade.
- Compare diferenças específicas em versões documentadas e teste migrações com dados representativos.

## Atividades

### Atividade 1 — Compare uma consulta de paginação
Use a tabela Produto(id, nome). Compare a documentação oficial de PostgreSQL, MySQL 8.4 e SQL Server. Converta a consulta “mostrar dez produtos a partir do 21º, em ordem de id” entre a sintaxe PostgreSQL/MySQL e a sintaxe SQL Server.

**Tarefas**
1. Escreva a consulta para PostgreSQL ou MySQL.
2. Escreva a versão para SQL Server.
3. Identifique uma semelhança e uma diferença concreta.
4. Explique por que ORDER BY precisa definir uma ordem previsível.

**Solução de referência:**
```sql
-- PostgreSQL ou MySQL 8.4
SELECT id, nome
FROM produto
ORDER BY id
LIMIT 10 OFFSET 20;
```

```sql
-- SQL Server
SELECT id, nome
FROM produto
ORDER BY id
OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;
```

Ambas selecionam colunas, usam FROM e ordenam por id; a forma de limitar e pular linhas difere. Como id deve ser único, ORDER BY id define desempate único. Consulte a versão específica antes de aplicar a mesma sintaxe a outro SGBD.

**Rubrica (0–3):** 1 ponto pelas duas consultas equivalentes; 1 por apontar corretamente a diferença de paginação; 1 por explicar a necessidade de uma ordem estável.

### Atividade 2 — Revise uma proposta de migração
Uma equipe quer migrar uma aplicação de PostgreSQL para MySQL e planeja trocar a configuração do driver, executar o schema existente e publicar. Faça uma revisão curta antes da decisão.

**Tarefas**
1. Liste quatro áreas que precisam de compatibilidade verificada.
2. Escolha duas consultas críticas para comparar resultado e tratamento de NULL.
3. Indique como validar constraints, migrations e transações no ambiente de destino.
4. Registre qual produto/versão e quais fontes oficiais sustentam a conclusão.

**Dica:** escolha recursos usados de fato pelo projeto, como identidade, upsert, paginação, funções de data e tipos.

**Solução de referência:** a proposta é insuficiente. Inventarie DDL/tipos/constraints, queries e funções, identidade/sequence, upsert/paginação, tratamento de NULL, transações/isolamento, drivers e migrations. Em base de teste com dados representativos, aplique migrations e compare resultados das consultas críticas, estados após operações e restauração. Registre versão exata do MySQL alvo e referências oficiais; ajuste as partes incompatíveis e repita a validação antes da publicação.

**Rubrica (0–4):** 1 ponto por cobrir sintaxe e tipos; 1 por tratar operações/transações; 1 por propor comparação de resultados e dados; 1 por registrar versão e documentação confiável.

## Critério de conclusão
Você concluiu quando explica ao menos uma semelhança e uma diferença concreta entre dialetos e propõe uma verificação de migração específica por produto e versão.

## Objetivo
Conectar-se a um PostgreSQL de estudo, inspecionar o banco com psql, criar e popular tabelas por scripts e executar alterações controladas com SQL.

## Teoria

### 1. Entenda servidor, banco, schema e conexão
PostgreSQL é um SGBD relacional que implementa SQL e oferece recursos próprios. O servidor pode hospedar vários bancos; dentro de cada banco, schemas organizam tabelas, views, funções e outros objetos. Uma conexão seleciona um servidor e um banco com um usuário autorizado.

Para conectar, identifique host, porta, banco, usuário e método de autenticação. Na instalação local, o host costuma ser `localhost); em Compose, um cliente dentro da mesma rede usa o nome do serviço, como `db), e a porta interna, normalmente 5432. Um cliente no host usa a porta publicada. Uma falha de conexão pode significar servidor parado, host/porta incorretos, banco inexistente ou credenciais/permissões inadequadas.

```sh
psql -h localhost -p 5432 -U estudo -d trilha_estudo
```

O comando pressupõe que o servidor local escuta na porta 5432, que o banco e o usuário existem e que a conexão está autorizada. Não coloque senhas reais diretamente em comandos que possam ficar no histórico ou em logs.

**Erro comum:** tentar resolver todo erro como senha incorreta sem verificar primeiro se o cliente alcança o host e a porta certos.

### 2. Use psql para explorar e executar scripts
psql é o cliente de terminal interativo do PostgreSQL. Os comandos com barra invertida são metacomandos do cliente, não SQL enviado ao servidor. Alguns úteis:

- `\conninfo` mostra informações da conexão atual.
- `\l` lista bancos visíveis.
- `\dt` lista tabelas no schema atual.
- `\d nome_tabela` descreve uma tabela.
- `\i caminho/arquivo.sql` executa um arquivo SQL.
- `\q` encerra o cliente.

O SQL termina com ponto e vírgula; uma quebra de linha sozinha não finaliza a instrução. Um script `.sql) versionado torna a criação de tabelas e os dados didáticos reproduzíveis. Para executar arquivo pelo terminal e parar no primeiro erro:

```sh
psql -h localhost -U estudo -d trilha_estudo -v ON_ERROR_STOP=1 -f scripts/01_schema.sql
```

CREATE DATABASE é uma operação administrativa e deve ser executada conectado a outro banco, como `postgres), por um usuário autorizado. Depois, conecte-se ao banco criado para criar tabelas e dados. Não confunda bancos diferentes com schemas do mesmo banco.

**Erro comum:** tentar criar um banco estando conectado a ele ou tratar `\dt) como uma instrução SQL.

### 3. Crie tabelas e altere dados com cuidado
DDL define a estrutura; DML insere, consulta, altera e remove linhas. Um fluxo simples pode criar tabelas, inserir dados e verificar os resultados:

```sql
CREATE TABLE cliente (
  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nome text NOT NULL
);

CREATE TABLE pedido (
  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  cliente_id integer NOT NULL REFERENCES cliente(id),
  status text NOT NULL,
  total numeric(10,2) NOT NULL CHECK (total >= 0)
);

INSERT INTO cliente (nome) VALUES ('Ana') RETURNING id, nome;
```

UPDATE e DELETE precisam de um alvo claro. Antes de alterar, execute como SELECT o mesmo filtro e confira as linhas. Acrescente WHERE de acordo com uma chave ou regra suficientemente específica. RETURNING mostra as linhas afetadas e é útil para confirmar o resultado no PostgreSQL.

```sql
UPDATE pedido
SET status = 'pago'
WHERE id = 42
RETURNING id, status;
```

Sem WHERE, UPDATE altera todas as linhas e DELETE remove todas as linhas da tabela. Um filtro com valor errado também pode atingir zero linhas, então confira a contagem e o resultado em vez de assumir que houve uma alteração.

**Erro comum:** executar UPDATE ou DELETE diretamente sem primeiro conferir o conjunto de linhas que o filtro seleciona.

### 4. Use transações para operações que precisam ficar juntas
Uma transação agrupa operações para que o conjunto seja confirmado com COMMIT ou desfeito com ROLLBACK. Isso é útil para ensaiar uma alteração e verificar seu efeito antes de mantê-la.

```sql
BEGIN;

UPDATE pedido
SET status = 'pago'
WHERE id = 42
RETURNING id, status;

-- Confira o resultado antes de confirmar.
ROLLBACK;
```

Após ROLLBACK, a alteração dessa transação não fica persistida. Se o resultado estiver correto e a operação for intencional, COMMIT confirma. Em psql, um erro pode deixar a transação atual em estado abortado até executar ROLLBACK. Transação não substitui backup, nem protege uma operação executada no banco errado.

**Checklist antes de uma escrita:**
- A conexão aponta para o host e o banco de estudo corretos?
- Você executou o filtro como SELECT e conferiu as linhas?
- O WHERE identifica o alvo que deseja alterar?
- RETURNING ou uma consulta posterior permite confirmar o resultado?
- A operação pode ser ensaiada numa transação e revertida?

## Resumo
- Conexão depende de host, porta, banco, usuário e autorização.
- psql mistura instruções SQL com metacomandos próprios iniciados por barra invertida.
- Scripts versionados recriam estrutura e dados didáticos; CREATE DATABASE é feito a partir de outro banco.
- Confira o alvo de UPDATE/DELETE antes de executar e use RETURNING para observar as linhas afetadas.
- BEGIN, COMMIT e ROLLBACK controlam a confirmação de um conjunto de alterações.

## Quiz
1. Quais informações básicas o psql usa para conectar a um servidor e banco? **Resposta:** host, porta, banco, usuário e credenciais/método de autenticação. **Feedback:** confirmar cada elemento ajuda a localizar falhas sem atribuí-las automaticamente à senha.
2. `\dt) é SQL executado pelo servidor? **Resposta:** não, é um metacomando do cliente psql para listar tabelas. **Feedback:** metacomandos começam com barra invertida.
3. Por que `CREATE DATABASE) deve ser executado conectado a outro banco, em vez do banco que será criado? **Resposta:** o banco alvo ainda não existe para receber a conexão; a criação é feita a partir de uma conexão já estabelecida e exige autorização. **Feedback:** depois de criado, conecte-se a ele para criar tabelas.
4. O que ocorre com `UPDATE pedido SET status = 'pago') sem WHERE? **Resposta:** todas as linhas da tabela são atualizadas. **Feedback:** confirme primeiro as linhas com um SELECT usando o filtro desejado.
5. Para que serve ROLLBACK depois de testar uma alteração dentro de BEGIN? **Resposta:** desfazer as alterações ainda não confirmadas nessa transação. **Feedback:** COMMIT confirma; ROLLBACK abandona o conjunto de mudanças.

## Práticas

### Atividade 1 — Conecte e reconheça o ambiente
Use uma instalação local ou o banco de estudo do Compose. Conecte-se ao banco de prática e registre o contexto da sessão.

**Tarefas**
1. Conecte usando host, porta, banco e usuário fornecidos pelo ambiente.
2. Mostre como verificar a conexão atual e listar tabelas.
3. Diferencie metacomando psql de SQL.
4. Diagnostique qual parâmetro verificaria para cada sintoma: conexão recusada, banco inexistente e autenticação recusada.

**Dica:** comece por disponibilidade do servidor e host/porta; depois confira nome do banco e usuário.

**Solução de referência:** entre com psql usando `-h), `-p), `-U) e `-d). Execute `\conninfo) e `\dt). `\conninfo) e `\dt) são metacomandos; `SELECT) é SQL. Conexão recusada aponta primeiro para servidor/host/porta/rede; banco inexistente pede conferir `-d); autenticação recusada exige conferir usuário, credencial e política de acesso.

**Rubrica (0–4):** 1 ponto pela conexão com parâmetros explícitos; 1 por verificar contexto e tabelas; 1 por distinguir metacomandos; 1 por relacionar cada falha à investigação adequada.

### Atividade 2 — Recrie esquema e dados de demonstração
Crie um arquivo `scripts/01_schema.sql) para tabela cliente e pedido. Cliente tem id e nome; Pedido tem id, cliente_id, status e total, com referência ao cliente e total não negativo. Insira duas linhas de cliente e três pedidos e registre o processo em um segundo script.

**Tarefas**
1. Separe o DDL do script de dados iniciais.
2. Execute os scripts no banco de estudo.
3. Use `\dt), `\d pedido) e SELECT para conferir estrutura e dados.
4. Explique por que esses scripts não substituem backup.

**Dica:** use a ordem de dependência: primeiro cliente, depois pedido.

**Solução de referência:** crie cliente com PK e nome obrigatório; crie pedido com PK, FK obrigatória para cliente e total com CHECK não negativo. Popule primeiro clientes e depois pedidos. Execute os arquivos com `psql -d trilha_estudo -v ON_ERROR_STOP=1 -f scripts/01_schema.sql) e o arquivo de dados. Scripts reproduzem estrutura e dados conhecidos para o exercício; não preservam automaticamente alterações futuras nem fornecem recuperação de um banco real.

**Rubrica (0–4):** 1 ponto por DDL coerente; 1 por respeitar a dependência FK ao inserir; 1 por executar e verificar scripts; 1 por distinguir reprodutibilidade didática de backup.

### Atividade 3 — Atualize com confirmação e reversão
Na tabela de pedidos de estudo, altere o status de um pedido identificado pelo id. Primeiro confira o alvo, depois teste a alteração em uma transação e decida se confirma ou desfaz.

**Tarefas**
1. Consulte o pedido pelo id e confirme a linha esperada.
2. Execute UPDATE com WHERE e RETURNING dentro de BEGIN.
3. Confira a alteração antes de decidir.
4. Use ROLLBACK para ensaiar ou COMMIT para persistir.
5. Explique o efeito de remover WHERE.

**Dica:** faça primeiro SELECT com o mesmo WHERE, e confirme se o id existe no banco certo.

**Solução de referência:**
```sql
BEGIN;
UPDATE pedido
SET status = 'pago'
WHERE id = 1
RETURNING id, cliente_id, status, total;
-- Inspecione o resultado e escolha uma opção:
ROLLBACK;
-- Para persistir uma alteração validada, use COMMIT no lugar de ROLLBACK.
```
O SELECT anterior deve mostrar somente o pedido id 1. Sem WHERE, todas as linhas seriam alteradas. Não execute COMMIT e ROLLBACK na mesma tentativa esperando que ambos tenham efeito: escolha um desfecho por transação.

**Rubrica (0–5):** 1 ponto por verificar o alvo; 1 por UPDATE com filtro; 1 por usar RETURNING; 1 por escolher corretamente entre confirmar e desfazer; 1 por explicar a consequência de omitir WHERE.

## Critério de conclusão
Você concluiu quando conecta-se ao banco correto, navega no psql, recria estrutura e dados de estudo com scripts e executa alterações com alvo verificado e resultado confirmado ou revertido conscientemente.

## Objetivo
Escrever e interpretar consultas SELECT com projeção, filtros, tratamento de NULL, ordenação, limites e parâmetros seguros, prevendo quais linhas e colunas serão retornadas.

## Teoria

### 1. Defina a forma do resultado
Uma consulta SELECT lê dados sem alterar a tabela. FROM indica a tabela ou fonte; a lista após SELECT escolhe as colunas e expressões que aparecem no resultado. Evite `SELECT *) em relatórios e integrações quando o consumidor precisa de um formato previsível: selecionar explicitamente as colunas reduz dados desnecessários e deixa o contrato visível.

Aliases com AS dão nomes claros ao resultado, inclusive para expressões. Por exemplo:

```sql
SELECT id, total AS valor_pedido
FROM pedido;
```

A consulta retorna duas colunas, chamadas id e valor_pedido. O alias não altera o nome persistido na tabela. Sem DISTINCT, linhas repetidas no resultado podem permanecer; selecionar menos colunas pode fazer linhas diferentes parecerem iguais, mas não elimina as linhas.

**Erro comum:** achar que o nome após AS renomeia permanentemente a coluna da tabela ou que SELECT remove duplicatas por padrão.

### 2. Filtre linhas com WHERE
WHERE mantém apenas linhas cuja condição resulta em verdadeiro. Comparações como `=), `<>), `>), `>=), `BETWEEN) e `IN) expressam critérios. AND exige que ambas as condições sejam verdadeiras; OR exige pelo menos uma. Use parênteses para tornar explícita a combinação quando houver mistura de AND e OR.

```sql
SELECT id, total, status
FROM pedido
WHERE status = 'pago'
  AND total >= 50;
```

Esse exemplo seleciona pedidos pagos cujo total é pelo menos 50. Texto usa aspas simples; identificadores normalmente não precisam de aspas duplas quando seguem convenções simples do PostgreSQL. Use valores monetários com tipos numéricos apropriados no banco, não com aproximação binária de ponto flutuante.

**Erro comum:** omitir parênteses em uma condição mista e obter resultado diferente do pretendido por causa da precedência dos operadores.

### 3. Trate NULL como ausência de valor conhecido
NULL não significa zero, string vazia ou falso. Uma comparação comum com NULL, como `status = NULL), resulta em desconhecido em vez de verdadeiro ou falso; por isso, a linha não passa no WHERE. Use `IS NULL) e `IS NOT NULL).

```sql
SELECT id, status
FROM pedido
WHERE status IS NULL;
```

A lógica SQL tem três resultados: verdadeiro, falso e desconhecido. Se qualquer condição necessária do AND for desconhecida, o resultado pode ser desconhecido; WHERE mantém somente o resultado verdadeiro. Com OR, uma condição verdadeira já torna a expressão verdadeira. Aprenda a analisar cada condição antes de combinar filtros.

**Erro comum:** escrever `coluna = NULL) ou comparar NULL com zero para representar ausência.

### 4. Ordene antes de limitar o resultado
ORDER BY define a ordem final. ASC é crescente e DESC decrescente. Sem ORDER BY, o banco pode retornar linhas em qualquer ordem; não assuma ordenação por chave primária, data de inserção ou ordem física.

Uma ordenação pode empatar. Acrescente uma coluna única como desempate quando for necessário ter uma sequência determinística, por exemplo `ORDER BY criado_em DESC, id DESC). No PostgreSQL, NULLs também têm posição definida pela ordenação padrão, mas você pode especificar `NULLS FIRST) ou `NULLS LAST) para explicitar a expectativa.

LIMIT restringe o número de linhas retornadas depois da ordenação. Para obter os dez pedidos mais recentes, ordene e limite juntos:

```sql
SELECT id, criado_em, total
FROM pedido
ORDER BY criado_em DESC, id DESC
LIMIT 10;
```

Sem uma ordem que diferencie os empates, quais linhas aparecem no limite pode variar. OFFSET pula linhas, mas páginas profundas podem ser caras e alterações simultâneas podem mover resultados; paginação por cursor/chave é aprofundada em outros contextos.

**Erro comum:** usar LIMIT 10 e esperar “os dez mais recentes” sem ordenar pela data.

### 5. Leia consultas com segurança e previsibilidade
Organize a consulta em uma forma legível: colunas selecionadas, fonte, filtros, ordenação e limite. Leia cada cláusula e preveja primeiro as linhas que sobrevivem ao WHERE; depois identifique as colunas projetadas, a ordem e o corte do LIMIT. Essa simulação ajuda a encontrar erro de lógica sem depender de adivinhação.

Quando valores vêm de usuário ou requisição, vincule-os por parâmetros preparados do driver/cliente. Não monte SQL concatenando texto não confiável. O formato do marcador depende da biblioteca usada (por exemplo, alguns drivers usam `$1)); placeholders são para valores, não substituem nomes dinâmicos de tabela ou coluna. Para ordenação escolhida pelo usuário, use uma lista permitida de opções no código.

**Erro comum:** interpolar entrada diretamente em uma string SQL e abrir caminho para injeção ou erros de aspas e tipos.

## Resumo
- SELECT escolhe colunas e expressões; FROM identifica a fonte.
- WHERE filtra apenas linhas cuja condição resulta em verdadeiro.
- NULL exige IS NULL/IS NOT NULL, e lógica SQL pode resultar em desconhecido.
- ORDER BY define a ordem; use desempate único para resultados previsíveis com LIMIT.
- Parâmetros do driver protegem valores fornecidos pelo usuário; não concatene entrada em SQL.

## Quiz
1. O que `SELECT id, total AS valor_pedido) altera? **Resposta:** o nome da coluna no resultado da consulta; não renomeia a coluna persistida. **Feedback:** alias é um rótulo de saída.
2. Qual filtro localiza pedidos sem status registrado? **Resposta:** `WHERE status IS NULL). **Feedback:** `status = NULL) não resulta em verdadeiro.
3. O que `WHERE ativo = true OR status = 'pago' AND total > 100) considera sem parênteses? **Resposta:** AND é avaliado antes de OR, portanto ativo verdadeiro basta; caso contrário, status deve ser pago e total maior que 100. **Feedback:** use parênteses para deixar a regra explícita e facilitar revisão.
4. Uma consulta aplica `LIMIT 10) sem ORDER BY. O que ela garante? **Resposta:** retorna no máximo dez linhas, sem garantir quais serão escolhidas nem sua ordem. **Feedback:** limite não define critério de seleção.
5. Como consultar os dez pedidos mais recentes com resultado repetível quando datas empatam? **Resposta:** ordenar por data decrescente e acrescentar uma chave única como desempate antes de LIMIT 10. **Feedback:** a chave adicional torna a ordem total entre linhas empatadas.

## Práticas

### Atividade 1 — Projete e filtre resultados
Considere Pedido(`id), `cliente_id), `status), `total), `criado_em), `observacao). Escreva uma consulta para listar id, status, total como valor_pedido e criado_em somente para pedidos pagos com total a partir de 100.

**Tarefas**
1. Escolha explicitamente as colunas.
2. Aplique os dois filtros exigidos.
3. Explique por que observar todos os campos com SELECT * não é necessário.

**Dica:** uma condição simples por regra torna a consulta fácil de conferir.

**Solução de referência:**
```sql
SELECT id, status, total AS valor_pedido, criado_em
FROM pedido
WHERE status = 'pago'
  AND total >= 100;
```
As colunas foram limitadas ao relatório e o alias melhora o rótulo de saída. Se total puder ser NULL, a comparação não seleciona essa linha; defina se isso é aceitável para a regra.

**Rubrica (0–3):** 1 ponto por selecionar as colunas corretas; 1 por alias e filtros corretos; 1 por explicar projeção e efeito de NULL.

### Atividade 2 — Interprete NULL e lógica booleana
Considere estes registros:
- (1, status='pago', total=80)
- (2, status=NULL, total=150)
- (3, status='aberto', total=200)
- (4, status='pago', total=150)

Determine quais ids retornam em cada consulta:
A. `WHERE status = 'pago' AND total >= 100)
B. `WHERE status IS NULL OR total >= 200)
C. `WHERE status = NULL)

**Tarefas**
1. Mostre o resultado de cada filtro.
2. Explique por que a consulta C não encontra o registro 2.
3. Reescreva C corretamente.

**Dica:** WHERE mantém somente linhas cuja condição inteira é verdadeira; desconhecido não é verdadeiro.

**Solução de referência:** A retorna id 4. B retorna ids 2 e 3. C não retorna linhas porque comparação com NULL produz desconhecido; a forma correta é `WHERE status IS NULL), que retorna id 2.

**Rubrica (0–4):** 1 ponto por cada resultado correto em A, B e C; 1 por explicar a comparação com NULL e corrigir a sintaxe.

### Atividade 3 — Encontre os dez maiores pedidos
Escreva uma consulta que retorne id, criado_em e total dos dez pedidos de maior total. Em caso de empate, o maior id vem primeiro. Exclua pedidos cujo total seja NULL.

**Tarefas**
1. Defina as colunas projetadas e o filtro.
2. Ordene pelo critério principal e pela chave de desempate.
3. Aplique LIMIT após a ordenação.
4. Explique o que mudaria se ORDER BY fosse removido.

**Dica:** uma ordem em duas colunas define como resolver empates.

**Solução de referência:**
```sql
SELECT id, criado_em, total
FROM pedido
WHERE total IS NOT NULL
ORDER BY total DESC, id DESC
LIMIT 10;
```
A consulta exclui valores desconhecidos, ordena maior total primeiro e resolve empates por id decrescente. Sem ORDER BY, não há garantia de que as dez linhas escolhidas sejam as de maior total.

**Rubrica (0–4):** 1 ponto pelo filtro de NULL; 1 pela ordenação principal; 1 pelo desempate; 1 pelo limite e explicação da ausência de ordem.

## Critério de conclusão
Você concluiu quando consegue escrever uma consulta para um cenário novo, prever as linhas que passam pelos filtros, tratar NULL corretamente e justificar a ordenação e o limite.

# 3.4 — Revisita contínua

## Objetivo
Manter estudos e projetos versionados, revisar periodicamente o histórico, remover branches concluídas quando seguro e organizar um README em inglês que permita entender o repositório.

## Teoria

### Versionar como hábito
Git é útil quando o histórico registra unidades de trabalho compreensíveis. Depois de uma mudança que forma um estado coerente, revise `git status` e o diff; então registre o que deseja preservar. Commits pequenos e explicativos ajudam a encontrar quando e por que algo mudou. Não é necessário criar um commit para cada tecla, e mudanças incompletas podem permanecer em uma branch de trabalho até fazer sentido registrá-las.

### Revisar o histórico e as branches
Revisitar `git log --oneline --graph --decorate` e `git status` ajuda a identificar commits vagos, branches antigas e mudanças não registradas. Antes de apagar uma branch, confirme se o trabalho foi integrado ou preservado em outro lugar. Branches locais e remotas são referências separadas; apagar uma não implica apagar a outra.

Uma revisão periódica também pode verificar README, `.gitignore`, issues abertas e arquivos gerados. Se um segredo aparecer, trate a credencial primeiro; editar o README ou apagar um arquivo da branch atual não apaga cópias do histórico.

### README e escrita técnica em inglês
O README de um repositório de estudos deve responder: qual é o propósito, como navegar, quais ferramentas são necessárias e como reproduzir os exercícios. Para cumprir o objetivo deste módulo, escreva o README, títulos dos commits de estudo e issues em inglês simples. Use frases curtas e vocabulário consistente. Inglês claro é mais útil que tradução literal rebuscada; preserve nomes oficiais de comandos e tecnologias.

## Resumo
- Registre estados coerentes e revise alterações antes de commitá-las.
- Use o histórico para entender a evolução e localizar mudanças.
- Apague branches só depois de confirmar que o trabalho está integrado ou preservado.
- README deve explicar propósito, organização, requisitos e uso.
- Nesta trilha, README, títulos de commits e issues do repositório de estudos ficam em inglês simples.
- Arquivos removidos da versão atual podem continuar no histórico; segredos exigem rotação e tratamento próprio.

## Verificação — quiz
1. Quando é razoável apagar uma branch concluída? **A)** Sempre que o nome incomoda. **B)** Após verificar que o trabalho foi integrado ou preservado. **C)** Antes de revisar o diff. **D)** Depois de apagar o repositório. **Resposta: B.**
2. Qual deve ser a função principal do README de estudos? **A)** Guardar tokens. **B)** Explicar propósito, organização, requisitos e como reproduzir o trabalho. **C)** Repetir todo o histórico Git. **D)** Substituir documentação de cada ferramenta. **Resposta: B.**
3. Um segredo foi removido do README atual. Isso prova que não existe mais no histórico? **A)** Sim. **B)** Não; ele pode permanecer em commits anteriores e deve ser revogado/rotacionado. **C)** Só se a branch tiver nome `main`. **D)** Sim, se o README estiver em inglês. **Resposta: B.**
4. Como escrever títulos de commits em inglês simples? **A)** Usar frases curtas que descrevam a mudança. **B)** Traduzir palavra por palavra sem revisar. **C)** Escrever apenas `update`. **D)** Omitir o verbo e o contexto sempre. **Resposta: A.**

## Prática — revisão periódica do repositório
Abra seu repositório de estudos e revise o estado, o histórico recente, branches locais e README. Escolha um commit vago para corrigir apenas se ainda for seguro e não tiver sido compartilhado; caso contrário, registre a convenção a adotar daqui em diante. Atualize o README em inglês com objetivo, estrutura, requisitos e instruções de uso. Liste branches que podem ser removidas e justifique que o trabalho está preservado.

**Aceite:** README em inglês simples com seções úteis; histórico recente compreensível; branches consideradas sem apagar trabalho não integrado; nenhum segredo presente nos arquivos versionados.

### Exercício integrador — recupere antes de consultar

Faça a primeira tentativa sem abrir as unidades anteriores, documentação ou comandos. Reserve até dez minutos e responda com suas próprias palavras:

1. Como uma edição passa da working tree para o staging e depois para um commit? Que inspeções você faz antes de registrar?
2. Como você distingue mudanças preparadas, não preparadas e não rastreadas? Que informação `git diff` e `git diff --staged` mostram?
3. Quando você escolheria merge, rebase ou cherry-pick? O que muda ao reescrever uma branch já compartilhada?
4. O que você faria ao encontrar marcadores de conflito? Quando pediria contexto ou abortaria a integração?
5. O que fazer quando um push é rejeitado porque o remoto avançou? Explique o papel de `fetch` e `pull`.
6. O que fazer se uma credencial real aparecer em um commit enviado ao remoto?

Depois de responder, consulte as unidades 3.1, 3.2 e 3.3 e compare cada resposta com o conteúdo. Em seguida, use um repositório de estudos para reunir evidências: `git status`, histórico recente em grafo, branch atual, README e uma explicação de como o projeto evita versionar arquivos locais sensíveis. Não cole URLs privadas, credenciais nem conteúdo sensível na entrega.

**Autocorreção:** dê 0 pontos a cada resposta ausente ou incorreta, 1 a uma resposta parcialmente correta e 2 a uma resposta correta e explicada. Total: 12 pontos. Para concluir, alcance pelo menos 10 pontos e não mantenha nenhum erro crítico: descartar trabalho sem inspeção, reescrever branch compartilhada sem coordenação ou tratar `.gitignore` como revogação de segredo.

**Retorno espaçado:** agende uma segunda tentativa para sete dias depois. Antes de reler o material, responda novamente às questões 1, 3, 5 e 6 e compare com a primeira tentativa. Registre uma coisa que lembrou com mais clareza e uma lacuna que ainda precisa revisar. Os sete dias são o intervalo inicial deste exercício; podem ser ajustados após observar como os alunos avançam.

## Critério de conclusão
Manter o repositório de estudos organizado, com README em inglês que permita a outra pessoa entender e usar o conteúdo, histórico legível e branches concluídas tratadas sem perda de trabalho.

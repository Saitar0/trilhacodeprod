# 6.2 — Estruturas básicas

## Objetivo
Organizar lógica em funções e representar informações com arrays e objetos, controlando parâmetros, retorno e escopo.

## Teoria

### Funções, parâmetros e argumentos
Uma **função** reúne uma tarefa que pode ser chamada com entradas. **Parâmetros** são nomes usados na definição; **argumentos** são valores passados na chamada. Definir uma função não executa seu corpo: a execução ocorre quando ela é chamada. Uma função deve ter responsabilidade compreensível e nome que indique seu propósito.

```js
function somar(a, b) {
  return a + b;
}

const resultado = somar(3, 4); // 3 e 4 são argumentos; a e b são parâmetros
```

### Retorno e responsabilidade
`return` encerra a execução da função e devolve um resultado; sem retorno explícito, a chamada produz `undefined`. `console.log` exibe um valor, mas não o devolve ao código que chamou a função. Separe cálculo de apresentação quando isso tornar a função reutilizável: retorne o resultado e deixe a chamada decidir como mostrá-lo.

### Arrays, objetos e coleção de entidades
Um **array** é uma sequência ordenada de valores acessada por índice, começando em zero. Um **objeto** reúne propriedades nomeadas, útil para representar uma entidade com campos relacionados. Escolha array para coleção ordenada e objeto para descrever uma coisa; uma lista de entidades costuma ser um array de objetos.

```js
const tarefa = { id: 1, titulo: "Revisar aula", ativa: true };
const tarefas = [tarefa, { id: 2, titulo: "Publicar", ativa: false }];
```

### Escopo e fluxo de dados
**Escopo** determina onde um nome pode ser acessado. Parâmetros e variáveis declarados dentro de uma função pertencem ao escopo local; `let` e `const` respeitam o bloco em que foram declarados. O código de fora não pode acessar diretamente uma variável local da função. Evite depender de variáveis globais implícitas: passe dados por argumentos e devolva resultados quando isso deixar dependências explícitas.

### Transformação e mutação
Transformar uma coleção e alterar a coleção original são operações diferentes. `filter()` devolve um novo array com os itens que passaram pelo teste; `sort()` reorganiza o array original e devolve uma referência a esse mesmo array. Para ordenar sem alterar a lista recebida, faça uma cópia rasa com `slice()` antes de chamar `sort()`.

```js
function ordenarPorPrioridade(tarefas) {
  return tarefas.slice().sort((a, b) => a.prioridade - b.prioridade);
}
```

O comparador numérico define a ordem crescente. Se duas prioridades forem iguais, retornar `0` indica que o par é equivalente para essa ordenação; em JavaScript moderno, a ordenação estável preserva a ordem relativa desses itens. A cópia do array não duplica os objetos dentro dele; nesta unidade, a função só reorganiza as referências, sem alterar as propriedades das tarefas.

Teste casos comuns e de borda: lista vazia, elemento ausente, valores repetidos e prioridades iguais. Separar transformação da apresentação torna a função mais fácil de reutilizar.

## Resumo
- Funções recebem argumentos por parâmetros e podem devolver valores com `return`.
- Exibir com `console.log` não substitui devolver um valor.
- Sem retorno explícito, o resultado é `undefined`.
- Arrays são sequências ordenadas; objetos descrevem valores por propriedades.
- Escopo limita onde nomes podem ser usados; prefira dependências explícitas.
- `filter()` cria um array filtrado; `sort()` altera o array original, então copie-o antes se precisar preservá-lo.
- Funções pequenas com propósito claro são mais fáceis de reutilizar e testar.
- Inclua casos de borda na validação do comportamento.

## Verificação — quiz
1. Qual é o papel de `return`? **A)** Repetir a função. **B)** Devolver um valor e encerrar a chamada. **C)** Criar um array. **D)** Tornar variável global. **Resposta: B.** `return` envia o resultado ao ponto de chamada e encerra aquela execução; exibir no console ou alterar escopo são outras ações.
2. Qual estrutura representa melhor uma lista ordenada de tarefas? **A)** Um array. **B)** Uma string única com todos os dados. **C)** Uma função sem retorno. **D)** Um booleano. **Resposta: A.** O array mantém uma sequência indexada e pode conter um objeto por tarefa; string, função e booleano não representam essa coleção estruturada diretamente.
3. Onde uma variável declarada com `const` dentro de uma função pode ser acessada? **A)** Em todo o computador. **B)** No escopo em que foi declarada, respeitando as regras de bloco. **C)** Em qualquer arquivo. **D)** Apenas no banco de dados. **Resposta: B.** O nome fica limitado ao escopo de função/bloco em que foi declarado; `const` não o torna global nem relacionado a arquivos ou banco de dados.
4. Uma função não executa `return`. O que sua chamada retorna? **A)** `null`. **B)** `false`. **C)** `undefined`. **D)** Um array vazio. **Resposta: C.** Se a execução termina sem retorno explícito, o valor da chamada é `undefined`; não é automaticamente `null`, `false` ou uma coleção vazia.
5. Após executar `const ordenadas = tarefas.sort(comparar);`, o que é verdade? **A)** `ordenadas` é uma cópia e `tarefas` fica intacta. **B)** `ordenadas` e `tarefas` referenciam o mesmo array, já ordenado. **C)** `sort()` sempre devolve `undefined`. **D)** `tarefas` vira um objeto. **Resposta: B.** `sort()` altera a ordem do array recebido e devolve esse mesmo array; para preservar a ordem original, ordene uma cópia, por exemplo `tarefas.slice().sort(comparar)`.

## Práticas

### 1. Guiada — diferencie exibição de retorno
Leia o código e preveja o valor de `resultado` e o que aparece no console.

```js
function calcularTotal(itens) {
  let total = 0;
  for (const item of itens) {
    total += item.preco;
  }
  console.log(total);
}

const resultado = calcularTotal([{ preco: 4 }, { preco: 7 }]);
console.log("retorno:", resultado);
```

**Tarefa:** ajuste a função para que a chamada devolva o total e não exiba nada por conta própria. Depois explique por que `total` não pode ser acessada diretamente fora da função.

**Dicas graduais:** (1) diferencie o valor impresso do valor devolvido; (2) acompanhe o escopo de `total`; (3) escolha em que ponto a função deve terminar e entregar o cálculo.

**Solução comentada:** substitua `console.log(total)` por `return total`. Assim, `resultado` recebe `11`; a segunda chamada de `console.log` exibe `retorno: 11`. `total` foi declarada dentro da função e seu nome só existe naquele escopo. A função pode devolver o valor calculado sem expor a variável local.

**Erro comum:** achar que `console.log(total)` faz a função retornar `total`; `console.log` tem o efeito de exibir, mas não entrega esse resultado ao chamador.

### 2. Independente — modele e conte tarefas
Modele três tarefas como objetos com `id`, `titulo` e `ativa`, reunidos em um array. Escreva `contarAtivas(tarefas)` para devolver quantas estão ativas. Use parâmetro e retorno; não leia variável global dentro da função.

Antes de executar, rastreie cada tarefa em uma tabela `título | ativa? | contador`. Verifique também `contarAtivas([])` e explique o resultado.

**Dicas graduais:** (1) cada objeto representa uma tarefa, e o array representa a coleção; (2) inicie o contador em zero; (3) incremente apenas quando `tarefa.ativa` for `true`.

**Critérios de aceite:** três objetos válidos; resultado corresponde à tabela; array vazio retorna `0`; dados entram por argumento e o total sai por `return`. A solução pode usar laço ou `filter().length`, desde que a escolha seja explicada.

### 3. Transferência — relatório de tarefas
Crie uma lista de objetos `{ id, titulo, ativa, prioridade }`. Escreva funções separadas para filtrar tarefas ativas, ordenar por prioridade crescente e calcular quantas estão ativas. Cada função deve receber os dados por parâmetro. As funções de filtro e ordenação devolvem resultados; não altere a lista original. Teste lista vazia e prioridades iguais.

**Entregue:** dados de entrada, três funções, resultado esperado para uma lista de pelo menos quatro tarefas, estado da lista original antes/depois e testes com `[]` e prioridades iguais. Na ordenação, use um comparador numérico e uma cópia rasa antes de `sort()`.

**Dicas graduais:** (1) `filter()` seleciona sem reorganizar a lista recebida; (2) `sort()` muta, então copie antes; (3) um contador pode ser implementado com laço e retornar zero para uma coleção vazia.

**Aceite:** funções têm responsabilidades distintas; entradas e saídas estão claras; resultado não depende de variável global; filtro, ordenação e contagem são demonstrados; lista vazia e prioridades iguais têm comportamento explicado; original permanece na ordem inicial.

**Rubrica (0–2 por critério):** (1) modelagem array de objetos apropriada; (2) parâmetros, escopo e retornos corretos; (3) transformações e mutação compreendidas; (4) casos de borda reproduzidos. `0` = ausente/incorreto, `1` = parcial, `2` = claro e verificável. Pronto com pelo menos 6/8 e sem mutação acidental da lista original.

**Aceite:** funções têm responsabilidades distintas; entradas/saídas estão claras; resultado não depende de variável global; casos normais e de borda são demonstrados; explique se a ordenação cria ou modifica array.

Explicar parâmetros, retorno, escopo e escolha entre array/objeto; produzir transformações que funcionam nos casos normais e de borda.

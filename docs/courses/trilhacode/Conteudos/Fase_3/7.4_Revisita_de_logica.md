# 7.4 — Revisita de lógica

## Objetivo
Transformar dados com métodos de array, compor funções, escolher entre arrays e objetos e estimar a complexidade linear em cenários comuns, reconhecendo pilhas e filas.

## Teoria
`map()` transforma cada elemento e retorna um novo array; `filter()` mantém elementos que passam por uma condição; `reduce()` combina itens em um acumulador. Esses métodos podem ser encadeados, mas encadeamentos longos devem permanecer legíveis. Funções pequenas tornam a transformação mais fácil de explicar.

Arrays são adequados para sequências e coleções; objetos são adequados para entidades com propriedades nomeadas ou consulta por chave. Um array de objetos é comum para listas de registros. Escolha estrutura conforme a operação principal: percorrer, ordenar, procurar por identificador ou representar estado.

**O(n)** descreve crescimento proporcional ao número de itens: percorrer uma lista inteira tende a fazer trabalho linear. Duas passagens sequenciais ainda crescem linearmente (aproximadamente 2n); loops aninhados sobre a mesma coleção podem crescer quadraticamente. São aproximações para comparar crescimento, não medições exatas de tempo.

Uma **pilha** segue LIFO (último a entrar, primeiro a sair), como histórico de desfazer. Uma **fila** segue FIFO (primeiro a entrar, primeiro a sair), como tarefas aguardando processamento. A implementação e as operações escolhidas afetam custo; `Array.shift()` pode deslocar elementos, então não assuma que toda operação de fila tem custo constante.

## Resumo
- `map` transforma, `filter` seleciona, `reduce` acumula.
- Arrays representam sequências; objetos representam propriedades nomeadas.
- O(n) indica trabalho que cresce proporcionalmente à quantidade de itens.
- Várias passagens sequenciais ainda são O(n); loop aninhado pode mudar a ordem de crescimento.
- Pilha é LIFO; fila é FIFO.
- Escolha operações/estrutura conforme uso e custo, não só pelo nome.

## Verificação — quiz
1. Qual método seleciona itens conforme uma condição? **A)** `filter`. **B)** `map`. **C)** `push`. **D)** `JSON.parse`. **Resposta: A.**
2. Percorrer uma lista uma vez para somar valores tem crescimento aproximado de: **A)** O(1). **B)** O(n). **C)** O(n²). **D)** O(2ⁿ). **Resposta: B.**
3. Em uma fila FIFO, qual elemento sai primeiro? **A)** O último inserido. **B)** O primeiro inserido. **C)** O menor número sempre. **D)** Um elemento aleatório. **Resposta: B.**
4. Qual exemplo representa uma pilha? **A)** Histórico de desfazer, removendo a ação mais recente primeiro. **B)** Pessoas atendidas por ordem de chegada. **C)** Catálogo ordenado por título. **D)** Mapa de rotas. **Resposta: A.**

## Prática — relatório sobre dados
Receba um JSON de pedidos fictícios com identificador, cliente, itens, total e status. Implemente funções para filtrar pedidos concluídos, transformar cada um em uma linha de relatório e calcular total por cliente. Compare uma implementação com uma passagem e outra com várias passagens. Descreva uma pilha de ações de desfazer e uma fila de pedidos de processamento para o mesmo domínio.

**Aceite:** operações devolvem resultados corretos para lista vazia e dados duplicados; função de transformação é separada do cálculo; complexidade é justificada pelo número de percursos; estruturas de pilha/fila respeitam LIFO/FIFO; custo de `shift` é reconhecido se usado.

1. A seleção contém pedidos 1 e 3. As linhas são `{ id: 1, cliente: "Lia", total: 30 }` e `{ id: 3, cliente: "Lia", total: 8 }`.

Uma implementação equivalente é `reduce((acumulado, pedido) => { acumulado[pedido.cliente] = (acumulado[pedido.cliente] ?? 0) + pedido.total; return acumulado; }, {})` sobre a lista filtrada.

4. A pilha é LIFO: a ação mais recente sai primeiro. A fila é FIFO: o pedido que chegou primeiro sai primeiro.
5. `filter()` e `map()` criam novos arrays; o exemplo não precisa alterar `pedidos`. Com lista vazia, seleção e linhas resultam em `[]`; o agrupamento resulta em `{}`. A implementação deve usar acumulador inicial para que `reduce()` também funcione com array vazio.

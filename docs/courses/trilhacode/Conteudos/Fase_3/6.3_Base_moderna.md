# 6.3 — Base moderna de JavaScript

## Objetivo
Ler e escrever JavaScript moderno com `let`/`const`, arrow functions, template strings, destructuring e operadores spread/rest.

## Teoria

### Declarações modernas e escopo
`let` e `const` têm escopo de bloco e tornam a intenção mais clara que `var`, cujo escopo é de função e comportamento de hoisting costuma surpreender iniciantes. Prefira `const` quando a associação não será reatribuída; use `let` quando for. Trocar `var` por `let`/`const` exige observar se o código depende do alcance da variável fora do bloco em que foi criada; não é uma substituição puramente mecânica.

### Arrow functions e retorno
Uma **arrow function** é uma forma concisa de criar função. Uma expressão pode retornar implicitamente; com corpo em bloco `{}`, use `return` explícito. Para retornar um literal de objeto com retorno implícito, envolva o objeto entre parênteses: `const criar = titulo => ({ titulo });`. Sem os parênteses, as chaves são interpretadas como corpo da função.

Arrow functions não criam seu próprio `this`, `arguments` ou contexto de construtor como funções tradicionais. Elas são úteis em callbacks que não dependem de `this` próprio; não as substitua mecanicamente em métodos de objeto ou funções construtoras.

### Template strings
Template strings usam crases e `${...}` para interpolar expressões e compor texto em várias linhas. A expressão é avaliada e convertida para texto; interpolar um objeto diretamente pode exibir uma representação pouco útil, então escolha a propriedade que comunica o dado desejado.

```js
const mensagem = `Tarefa: ${tarefa.titulo}`;
```

### Destructuring
**Destructuring** extrai valores de arrays ou propriedades de objetos em variáveis. A extração não apaga nem altera a origem; os nomes extraídos precisam corresponder às propriedades desejadas, salvo quando se usa renomeação. Para arrays, a posição determina o valor extraído; para objetos, a propriedade nomeada é a referência.

### Spread e rest
**Spread** (`...`) expande elementos ou propriedades em uma nova composição. **Rest** usa a mesma notação para reunir os itens restantes em um array ou objeto; a posição e o contexto determinam qual papel está sendo usado.

Em objetos e arrays, spread faz cópia rasa: a estrutura externa é nova, mas objetos aninhados continuam compartilhados. Alterar uma propriedade primitiva de topo na cópia não muda a origem; alterar uma propriedade de um objeto interno compartilhado pode mudar os dois. Faça cópia de níveis aninhados explicitamente quando precisar separá-los, e não use spread como sinônimo de imutabilidade.

```js
const tarefa = { id: 7, titulo: "Estudar", ativa: true };
const { titulo, ...dadosRestantes } = tarefa;
const atualizar = (item, patch) => ({ ...item, ...patch });
const mensagem = `Tarefa: ${titulo}`;
```

Use esses recursos quando deixarem o fluxo mais claro; concisão não deve esconder transformação ou mutação.

## Resumo
- `let`/`const` têm escopo de bloco; `var` tem regras diferentes e raramente é necessário no código novo.
- Arrow functions podem retornar implicitamente expressões, mas blocos precisam de `return`.
- Template strings interpolam expressões com `${}`.
- Destructuring extrai valores de estruturas.
- Spread expande; rest reúne os elementos restantes.
- Cópia com spread é rasa; dados internos ainda podem ser compartilhados.
- Arrow functions não têm `this` próprio; preserve funções tradicionais onde o método ou construtor depende desse comportamento.

## Verificação — quiz
1. Em uma arrow function com corpo `{ ... }`, como retornar o resultado? **A)** O bloco retorna implicitamente. **B)** Usar `return`. **C)** Usar `spread`. **D)** Não é possível. **Resposta: B.** Chaves indicam um corpo de bloco e não retornam automaticamente; `return` encerra a chamada com o valor. Retorno implícito ocorre em corpo de expressão sem essas chaves.
2. O que `${nome}` faz numa template string? **A)** Declara variável global. **B)** Insere o valor da expressão no texto. **C)** Cria um módulo. **D)** Clona o objeto. **Resposta: B.** A expressão entre `${}` é avaliada e interpolada. Ela não declara variáveis nem cria cópias ou módulos.
3. Em `const copia = { ...original }`, a cópia é: **A)** Profunda em qualquer nível. **B)** Rasa; propriedades aninhadas podem continuar referindo os mesmos objetos. **C)** Imutável. **D)** Uma string. **Resposta: B.** O objeto externo é novo, mas valores que são objetos continuam compartilhados. `const` também não congela propriedades.
4. Em `const { titulo, ...resto } = tarefa`, o que `resto` representa? **A)** Propriedades restantes. **B)** O título apenas. **C)** Um array de índices. **D)** Uma função. **Resposta: A.** No padrão de objeto, o rest reúne as propriedades que não foram extraídas antes; `titulo` fica em sua própria variável. O resultado não é um array.
5. Qual expressão cria uma arrow function que retorna um objeto `{ titulo: "Aula" }` implicitamente? **A)** `() => { titulo: "Aula" }` **B)** `() => ({ titulo: "Aula" })` **C)** `() => return { titulo: "Aula" }` **D)** `() => [titulo: "Aula"]` **Resposta: B.** Os parênteses fazem o literal ser interpretado como expressão retornada. Na alternativa A, as chaves iniciam o bloco da função e não há retorno; C tem sintaxe inválida sem corpo em bloco; D não representa um objeto válido nesse formato.

## Práticas

### 1. Guiada — corrija retorno e literal de objeto
Analise duas funções e preveja o resultado das chamadas:

```js
const dobrar = (valor) => {
  valor * 2;
};

const criarTarefa = (titulo) => { titulo: titulo };
```

**Tarefa:** ajuste as funções para que `dobrar(4)` resulte em `8` e `criarTarefa("Estudar")` resulte em `{ titulo: "Estudar" }`. Use retorno implícito onde couber e explique por que as versões originais não entregam esses valores.

**Dicas graduais:** (1) observe se o corpo é expressão ou bloco; (2) procure um `return` no bloco; (3) em objeto retornado implicitamente, diferencie as chaves do objeto das chaves do bloco.

**Solução comentada:** `const dobrar = valor => valor * 2;` usa corpo de expressão e retorna implicitamente. `const criarTarefa = titulo => ({ titulo });` usa parênteses para que as chaves sejam interpretadas como literal do objeto; a propriedade shorthand `titulo` usa o valor do parâmetro de mesmo nome. Nas versões iniciais, a primeira descarta o resultado da expressão dentro do bloco e a segunda interpreta `titulo:` como rótulo de instrução, sem devolver objeto.

**Erro comum:** remover chaves de um corpo com várias instruções sem revisar o fluxo, ou presumir que qualquer bloco de arrow function retorna a última expressão.

### 2. Independente — detecte compartilhamento em uma cópia
Considere:

```js
const original = { titulo: "Aula", meta: { concluida: false } };
const copia = { ...original };
copia.titulo = "Revisão";
copia.meta.concluida = true;
```

Antes de executar, preveja os valores de `original.titulo`, `original.meta.concluida`, `copia.titulo` e `copia.meta.concluida`. Depois explique qual alteração ficou isolada e qual foi compartilhada. Proponha uma cópia que também separe `meta` para este objeto conhecido e raso.

**Dicas graduais:** (1) spread cria outro objeto externo; (2) confira se `meta` também foi recriada; (3) copie explicitamente `meta` ao compor o novo objeto.

**Gabarito:** título original continua `"Aula"`; título da cópia vira `"Revisão"`; `meta.concluida` fica `true` nos dois, pois ambos apontam para o mesmo objeto interno. Para este formato conhecido: `const copiaSeparada = { ...original, meta: { ...original.meta } };`. Isso separa um nível específico, não faz cópia profunda arbitrária.

### 3. Transferência — refatore sem alterar o comportamento
Refatore o trecho legado abaixo. Use `const`/`let`, arrow functions onde forem adequadas, template string, destructuring e spread/rest. Preserve os textos e valores produzidos.

```js
var tarefa = { id: 12, titulo: "Estudar", ativa: true, meta: { categoria: "JS" } };

function descrever(item) {
  return "Tarefa " + item.id + ": " + item.titulo;
}

function atualizar(item, novoTitulo) {
  var copia = Object.assign({}, item);
  copia.titulo = novoTitulo;
  return copia;
}

function separarId(item) {
  var id = item.id;
  var titulo = item.titulo;
  return { id: id, titulo: titulo };
}
```

**Entregue:** código refatorado, saída de `descrever(tarefa)`, comparação da tarefa original antes/depois de `atualizar`, resultado de `separarId` e uma nota sobre a propriedade aninhada `meta`. Crie também um helper `semId(item)` que use rest para reunir e devolver as propriedades restantes; para `tarefa`, o resultado contém `titulo`, `ativa` e `meta`. Não converta mecanicamente funções que precisem de `this` próprio.

**Dicas graduais:** (1) `descrever` pode usar retorno de expressão; (2) o novo objeto pode ser criado com spread e sobrescrita de `titulo`; (3) em `separarId`, extraia `id` e `titulo` e reúna o resto; (4) uma cópia rasa ainda compartilha `meta`.

**Aceite:** saídas preservadas (`Tarefa 12: Estudar` e `{ id: 12, titulo: "Estudar" }`); atualização devolve título novo sem alterar o título original; `semId` devolve as propriedades restantes; solução demonstra todos os recursos pedidos; limitação rasa em `meta` identificada e ausência de promessa de imutabilidade profunda.

**Rubrica (0–2 por critério):** (1) escolha correta de `const`/`let` e arrow; (2) template e destructuring/rest legíveis; (3) spread preserva os valores externos sem ocultar compartilhamento interno; (4) saídas e comportamento original verificados. `0` = ausente/incorreto, `1` = parcial, `2` = claro e demonstrado. Pronto com pelo menos 6/8 e sem regressão de retorno ou mutação não identificada.

**Aceite:** mesmo resultado para os casos usados; nenhuma reatribuição de `const`; `return` presente em corpos com bloco; transformações não alteram objetos originais sem intenção; uso de arrow não quebra dependência de `this`.

## Checklist de entrega

- [ ] Três opções foram selecionadas pela regra da rotação; uma opção pendente foi escolhida e o tipo está identificado.
- [ ] Projeto de tipo do Trilho B não é duplicação do projeto principal do Trilho A.
- [ ] README define usuário/cenário, problema técnico, escopo excluído e contrato de aceite.
- [ ] Base mínima da Fase 5 foi incluída quando necessária (schema, migrations e API simples conforme tipo).
- [ ] Teste reproduzível prova o problema central; resultado esperado e evidência estão registrados.
- [ ] Dockerfile constrói a fatia e pipeline executa gates antes de implantar.
- [ ] Ambiente de teste é isolado, configuração é parametrizada e segredos não entram em imagem/log/Git.
- [ ] Métrica/log/painel específico do tipo foi produzido com labels controladas e sem dado sensível.
- [ ] Implantação está ligada ao commit/imagem e há evidência de health check.
- [ ] Rollback ou recuperação considera migrations e estado persistente.
- [ ] README explica reprodução, limites, custos/limites e encerramento dos recursos.
- [ ] Tabela de cobertura só foi atualizada após demonstração de aceite.
